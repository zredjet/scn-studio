# {{title}}（作品フォルダ）

この作品フォルダで作業するAIエージェント（Claude Codeなど）向けの指示書。`scn new` が共通のひな形から作った。作品のきまりは、最後の節に書き足す。

## 最初に読むもの

- `concept.md`：企画書。ログライン、テーマ、エンディング一覧。迷ったらここに立ち返る。
- `style.md`：文体の方針と文体見本。本文を書くときは必ず従う。
- `bible/entries/character/`：キャラクター。口調メモ、一人称、欲求、葛藤。
- `variables.yaml`：使える変数。新しい変数が要るときは、ここに宣言を足す。
- `FORMAT.md`：`.scn` の書き方と、作品フォルダの規約。

## 書いてよいところ、書き換えないところ

- 本文の無いシーン（スタブ）と、まだ無いシーンには、本文を書いてよい。AIが作った、または本文を書いたシーンは、メタ情報の `status` を `ai-draft` にする。
- 人が書いた行は書き換えない。直したほうがよいと思ったら、変更案を `ai/proposals/` に日付つきのMarkdownで書く（対象の行ID、今の文、案、理由）。
- 行ID（行末の `^k3f9` など）を手で付けない、消さない、変えない。新しい行の行IDは `scn fmt` で付ける（進め方の4）。
- `concept.md`、`style.md`、`FORMAT.md` は、頼まれたときだけ変える（`FORMAT.md` は `scn format-doc` で書き直す）。

## 進め方

コマンドはツールのCLI `scn` を使う（ツールのリポジトリで `cargo install --locked --path crates/scn-cli` を実行すると入る）。どれも作品フォルダで実行する。

1. 書き始める前に `scn fmt --check .` を実行する。行IDの無い行（人が書いた行など）があれば、先に `scn fmt .` で行IDを付けておく（`--provenance` は付けない）。後で付ける行IDを、自分が書いた行のものだけにするため。
2. いきなり本文を書かない。上から順に、スタブ（見出し・要約・出口）→ 展開メモ（シーンの流れ、登場キャラ、使う変数）→ 本文、と降りていく。
3. 分岐を足すときは、どのエンディングへ向かう分岐かを `concept.md` のエンディング一覧と照らし、条件に使う変数を `variables.yaml` で確かめる。作品の構造は `scn graph .` で確かめられる（シーンごと。`--level chapter` で章ごと、`--level route` でルートごと。`--json` でJSON）。
4. 書き終えたら、行IDを付けて、出自を記録する。
   - `scn fmt . --provenance external:claude-code --model <モデル名>` を実行する。行IDの無い行に行IDを付け、付けた行を `ファイル:行:列 ^ID` の形で出し（`--json` を付けるとJSON）、付けた行IDを AI が書いた行として `ai/provenance.jsonl` の末尾に書き足す。整形はしない。`project.toml` にエラーがあれば何もせずに終了コード2で止まるので、`project.toml` を直してからやり直す。
   - 人が書いた行には行IDを付けない（手順1で先に付けておく）ので、記録されるのは自分が書いた行だけになる。AI が書いた行の一覧は `scn provenance .` で見られる。
5. 検証する。`scn check .` を実行する。
   - 本文、設定ファイル、企画書、変数の宣言の診断が、`ファイル:行:列 コード メッセージ ^行ID` の形でまとめて出る（`--json` を付けるとJSON）。
   - エラー（`E` で始まる診断）は必ず直す。警告（`W`）は理由を確かめ、直すか、残す理由を報告に書く。情報（`I`）は直さなくてよい。
   - 終了コードは、エラーが無ければ0、エラーがあれば1、作品フォルダでない（`project.toml` が無い）などで検証できなければ2。
6. 報告には、作ったシーン、書いた分量、使った変数、付けた行IDの数、残った警告とその理由を書く。
