# .scn 形式仕様 v0

状態：v0確定（2026-10-07）。未決事項はT0-2ですべて決めた（経緯は `docs/decisions.md` の D016〜D034）。「17. IRの形」はT0-4で実装に合わせて決めた（D036）。6節（閉じ括弧の後ろがインライン命令だけの台詞）、5節（IDの無い見出し）、9節（行IDの付与）はT1-2で補った（D041）。16節の設定ファイルの診断（E801〜W804）と、17節の索引はT1-3で足した（D042）。16節の検証の段階1（`scn check`）と、7節の W406 はT1-4で足した（D043）。9節の分割の細部（字下げ、台詞の括弧の中）はT1-7で補った（D046）。16節の設定DBの値の検査（W805・W806）はT1-10で足した（D049）。14節の評価の規則（プレビュー）はT1-11で足した（D050）。

この仕様は、`.scn` ファイルの書き方と、パーサが返す結果（AST・IR・診断）の約束を定める。作品フォルダの `.scn` 以外のファイル（`project.toml`、変数、素材カタログ、設定DB、企画書など）の規約は `docs/spec/project-files.md` にある。作品フォルダの `FORMAT.md` には、この仕様の1〜16節と、その規約が入る。プロジェクト全体の設計は `docs/design.md`、用語は `docs/glossary.md` を参照。

## 1. 基本方針

- 1行が1つの要素になる、行指向の形式にする。日本語の原稿として読めることと、機械が曖昧なく読めることを両立させる。
- 演出は意味名で書く（`@背景 屋上/夕方`）。ファイル名やエンジンの命令は書かない。
- パーサはエラー回復を行う。誤りは診断として返し、残りの解析は続ける。

## 2. ファイル

- 拡張子は `.scn`。文字コードはUTF-8。先頭のBOMは読み飛ばし、書き出すときは付けない。
- 改行はLFとCRLFの両方を受け付ける。保存するときは、元のファイルの改行を保つ。
- 1ファイルを1章として使うことを想定する。1ファイルに複数のシーンを置ける。
- 形式のバージョンは、プロジェクトの `project.toml` の `format_version` で1つだけ持つ。

## 3. ファイルの構造

```
[章見出し]           # 第1章 放課後
シーン*
シーン = シーン見出し [メタ情報ブロック] 本文行*
```

- 章見出し（`# ` で始まる行）は任意で、ファイルの先頭（空行とコメントを除く）に1つだけ置ける。
- ファイルの先頭以外にある `# ` の行は、章見出しにならない。W112 を出し、地の文として扱う。
- 最初のシーン見出しより前に、章見出し・空行・コメント以外の行があれば W101 を出し、その行は無視する（先頭以外の `# ` の行がシーンより前にあれば、W112 と W101 の両方を出す）。

## 4. 行の分類

各行は、次の順で処理してから分類する（`@raw` ブロックの中の行は除く。15節）。

1. 行末の半角空白とタブを取り除く。行頭と同じく見た目の整形用として扱い、行IDの切り出しより前に行う（行IDの後ろに見えない空白があっても、行IDとして読む）。全角空白は取り除かない。
2. 行頭の半角空白とタブを読み飛ばした残りが `//` で始まる行は、コメントとし、ここで処理を終える。コメントの行からは行IDを切り出さない（行をコメントアウトしたときに、W303 や E304 を出さない）。
3. 行末の行ID（` ^xxxx`、9節）を切り出す。
4. 行頭の半角空白とタブを読み飛ばす。これは見た目の整形用で、意味を持たない。全角空白（U+3000）は読み飛ばさず、本文の一部として扱う。
5. 行頭が `\` なら、その `\` を取り除き、残りを地の文として分類する。続く文字は何でもよい。記号（`\@`、`\-`、`\/`、`\#`、`\\`）を本文として書くときや、台詞の形をした地の文（`\窓の外から「おーい」`）を書くときに使う。`\` で始まる地の文は `\\` と書く。

分類は上から順に判定し、最初に当てはまったものに決める。

| 順 | 条件 | 種類 |
| --- | --- | --- |
| 1 | 何も残らない | 空行 |
| 2 | `//` で始まる | コメント |
| 3 | `# ` で始まり、ファイルの先頭にある | 章見出し |
| 4 | `## ` で始まる | シーン見出し |
| 5 | `---` だけで、シーン見出しの直後にある（またはメタ情報ブロックの中にある） | メタ情報の区切り |
| 6 | `@` で始まる | ディレクティブ |
| 7 | `-` の後に半角空白が続くか、`-` だけ | 選択肢（選択ブロックの外なら E105 を出し、地の文として扱う） |
| 8 | `->` で始まる | ジャンプ |
| 9 | 台詞の形に当てはまる（6節） | 台詞候補 |
| 10 | 上のどれでもない | 地の文 |

- 3の条件に当てはまらない `# ` の行（ファイルの先頭に無いもの）は、10の地の文になる（3節、W112）。
- 空白は、半角空白、タブ、全角空白（U+3000）を指す。ただし行頭で読み飛ばすのと行末で取り除くのは、半角空白とタブだけ（上の1と4）。

## 5. シーン見出しとメタ情報

```
## 放課後の屋上 #s012
---
summary: 灯が転校を打ち明けかける
status: draft
route: 共通
tags: [屋上, 転校]
---
```

- 見出しは `## タイトル #シーンID`。行末の最後の ` #` 以降がシーンIDで、それより前がタイトルになる。
- シーンIDは英数字（`A-Z`、`a-z`、`0-9`）と `_` で、1文字以上書く。大文字と小文字は区別する。プロジェクト全体で一意にする。重複したら、後から現れたほうに E108 を出す。ファイルはパスの辞書順、ファイル内は行の順で比べる。
- ` #` 以降が上の形に合わなければ（`#帰り道`、`#s-1`、` #` の後が空）、E111 を出し、IDの無い見出しとして扱う（W107 は出さない）。タイトルは、最後の ` #` より前の部分にする。
- ` #` の無い見出しには W107 を出す。IRでは仮のID（`_anon_<ファイル名>_<番号>`。ファイル名は `story/` からのパスの拡張子を除き、`/` を `_` にしたもの（`story/part1/ch01.scn` なら `part1_ch01`、`story/` の直下なら拡張子を除いたファイル名。T2-10、D061）。番号は、そのファイルの中でIDの無いシーンを1から数えたもの。同じファイル名になる章（`story/part1/ch01.scn` と `story/part1_ch01.scn`）があれば、それらをまとめてパスの順に数える）を付けるが、ジャンプ先には指定できない。シーンIDはジャンプに書く名前なので、人（またはAIエージェント）が付ける。整形コマンド（`scn fmt`）は付けない（D041）。
- メタ情報ブロックは任意。見出しの次の行が `---` のときだけ始まり、次の `---` で終わる。閉じの `---` は、次のシーン見出しより前（無ければファイルの終わりまで）でだけ探し、その範囲に無ければ閉じていないものとする。シーン見出しは、メタ情報の中でも見出しとして読む。
- 中身はYAMLの一部（`キー: 値`、値は文字列か `[a, b]` 形式のリスト）だけを受け付ける。キーは空白と `:` を含まない1文字以上で、`:` の後は半角空白か行末。
- 閉じたブロックの中では、空行とコメントの行は読み飛ばし、`キー: 値` の形でない行には E114 を出して読み飛ばす。
- 閉じていなければ E102 を出し、`---` の次の行から `キー: 値` の形の行が続く間だけをメタ情報とみなして回復する（コメントの行は読み飛ばす。空行やシーン見出しなど、形の違う行が来たら終える）。
- 同じキーが2回以上あれば、後の値を使い、W113 を出す。

| キー | 値 | 意味 |
| --- | --- | --- |
| `summary` | 文字列 | 要約。プロットカードに表示する |
| `status` | `draft` / `writing` / `done` / `ai-draft` | 状態。それ以外の値は E110 |
| `route` | 文字列 | ルート名。フロー図のグループ分けに使う |
| `tags` | リスト | 自由なタグ |

- 上の表に無いキーは I109 を出したうえで、文字列としてIRに渡す。
- **スタブ**は、本文に台詞・地の文が1行も無いシーンを指す。状態の値ではなく、内容から決まる。

## 6. 台詞

```
灯「やっと来た。遅いよ」 ^k3f9
灯（？？？）「誰？」
灯『……言えるわけないよ』
```

- 形は `話者「本文」`。表示名を上書きするときは `話者（表示名）「本文」` と書く。表示名の括弧は全角の（）。表示名は空でもよい（`灯（）「……」`。名前を出さずに表示するときに使う）。

### 括弧と表示スタイル

```toml
[dialogue.brackets]
"「」" = "normal"
"『』" = "thought"   # 心の声
```

- 台詞に使える括弧の種類と表示スタイルは、`project.toml` の `[dialogue.brackets]` で決める。キーは開き括弧と閉じ括弧の2文字（互いに違う文字）、値は表示スタイルの名前（`normal`、`thought` などの英字の名前）。
- この節を書くと、その一覧が既定を置き換える（「」も使うなら書く）。書かなければ「」（`normal`）だけを使う。プロジェクトの外で1ファイルだけを解析するときも、この既定を使う。
- 括弧を1組も書かない（空の）`[dialogue.brackets]` や、1組も読めないとき（E802）は、既定の「」を使う（D042）。
- コアは表示スタイルの値を解釈しない。IRの台詞に `style` として渡し、見せ方はプレビューと出力プロファイルで決める。

### 台詞の判定

判定は2段階で行う。

1. **構文解析**：行頭から、空白（4節）と括弧（登録済みの開き括弧・閉じ括弧と、全角の（））を含まない文字が1〜20文字続き、その後に任意で（表示名）、その後に登録済みの開き括弧が来れば、**台詞候補**とする。この段階では設定DBを見ない。
2. **意味解析**：話者を、キャラクターのID、名前、呼び名の順に照合する。同じ段で2人以上のキャラクターに一致したら、解決できないものとする。
   - 閉じ括弧の後に文が続く場合（`彼は「行こう」と言った。`）は、話者を解決できてもできなくても、診断を出さずに地の文として扱う（小説の体裁で書いた行と同じ扱い）。
   - 閉じ括弧の後ろが、インライン命令（`{w …}`・`{p}`・`{se …}`・`{speed …}`。8節）と空白だけの場合（`灯「またね」{p}`）は、文が続くとはみなさない。変数の埋め込み、ルビ、傍点は文を作るので、それだけでも文が続くものとする。命令として読めないもの（W405）は文字なので、文が続くものとする。
   - それ以外で、解決できれば台詞にする。IRでの話者はキャラクターIDにする。閉じ括弧の後ろのインライン命令は、台詞の本文の末尾に付け、間の空白は捨てる。
   - 解決できず、閉じ括弧の後ろに文が続かない場合（行が閉じ括弧で終わるか、後ろがインライン命令と空白だけ）は、W202 を出して地の文として扱う。
   - 地の文として扱うときは、話者・（表示名）・括弧・本文・閉じ括弧・後ろの文を、書かれたとおりに並べて本文にする。
   - 未登録の話者（店員などのモブ）の台詞を書くときは、設定DBにキャラクターとして登録する。台詞の形をした地の文は、行頭の `\` で台詞の判定を止められる（4節）。

### 複数行にまたがる台詞

- 閉じ括弧が同じ行に無いときは、次の行以降を続きとして読み、閉じ括弧のある行で終える。行IDはその最後の行の末尾に付ける。
- 閉じる前に、空行、シーン見出し、ディレクティブ、選択肢の行、ジャンプの行が来るか、ファイルが終わったら、E201 を出し、その直前で台詞を終えて回復する。
- 途中のコメントの行は飛ばす（台詞の本文に含めず、打ち切りもしない）。
- 途中の `# ` で始まる行は、台詞の続きとして読む（地の文ではないので W112 は出さない）。
- 本文の中の同じ種類の括弧は、入れ子として数える。
- IRでは、行の境目に改行の要素（`line_break`）を挟む。改行をどう出力するかは、出力プロファイルで決める。

## 7. 地の文と空行

- 地の文は、行頭の全角空白（字下げ）も含めてそのまま本文にする。
- 空行は段落の区切りにする。同じブロックの中で、前後を台詞か地の文の行に挟まれた空行だけを、IRの `break` にする。間にあるコメントは飛ばして判定し、連続する空行は1つの `break` にまとめる。
- ディレクティブ、ジャンプ、選択肢の行、ブロックの前後にある空行は、見た目の整形として捨てる。
- `break` をどう出力するか（小説の体裁での段落、ADVでの改ページなど）は、出力プロファイルで決める。
- 空行が閉じていない台詞を打ち切る働き（6節、E201）は、`break` になるかどうかに関わらない。
- 行頭（行頭の半角空白とタブの後ろ）が全角の `＠`・`－＞`・`ー＞`・`＞`・`＃＃` の地の文には、W406 を出す（ディレクティブ・ジャンプ・シーン見出しのつもりの誤入力に見えるため。D043）。地の文のまま扱う。行頭の `\` で始めた行（4節）と、全角空白の後ろにある場合は出さない。台詞候補の形の行（`＠灯「…」` など。6節）には出さない（話者を解決できない W202 などで分かるため）。

## 8. 文中の記法

台詞の本文、地の文、選択肢の表示文、`@選択` の問いかけ文で使える。

| 記法 | 書き方 | 備考 |
| --- | --- | --- |
| ルビ | `\|親文字《るび》` または `｜親文字《るび》` | 小説投稿サイトと同じ |
| 自動ルビ | `漢字《かんじ》` | 直前に続く漢字（`々〆ヵヶ` を含む）を親文字にする |
| 《 そのもの | `\|《` または `｜《` | ルビにしない |
| 傍点 | `《《強調》》` | |
| ウェイト | `{w 0.5}` | 秒 |
| 改ページ | `{p}` | |
| 文中の効果音 | `{se ドア}` | 意味名 |
| 文字速度 | `{speed 遅}` | `遅` / `普通` / `速` |
| 変数の埋め込み | `{=湊.名前}` | 中身は式（14節） |
| 波括弧そのもの | `{{` と `}}` | |

- 知らないインライン命令と、値の合わないインライン命令（`{w 長め}`、`{speed 速すぎ}`）には W405 を出し、そのまま文字として扱う。
- 閉じていない `{` は文字として扱う。

## 9. 行ID

```
灯「やっと来た。遅いよ」 ^k3f9
```

- 形は、1つ以上の半角空白に続く `^` と、`[0-9a-z]` の4〜12文字。
- 行末が「1つ以上の半角空白、`^`、1文字以上の英数字（`[0-9A-Za-z]`）」で終わる行は、その部分を行IDの候補として切り出す。候補が上の形に合わなければ（大文字を含む、短い、長い）、E304 を出し、候補を本文から取り除いたうえで、行IDの無い行として扱う（I302 は出さない）。
- `^` の後に英数字以外を含むもの（`^_^`）や、`^` の前に半角空白の無いものは、行IDとみなさず、本文の一部にする。
- 行IDを持てるのは、台詞（複数行なら最後の行）、地の文、`@選択` の行、選択肢の行だけ。それ以外の行に付いていれば W303 を出して無視する。
- プロジェクト全体で一意にする。重複したら、後から現れたほうに E301 を出す。
- 行IDを持てる行（台詞、地の文、`@選択` の行、選択肢の行）に行IDが無ければ、I302 を出す。**パーサは行IDを付けない**。付与はフェーズ1の整形コマンド（`scn fmt`）とエディタが行う。
- 付与のきまり（`scn fmt` はT1-2で実装。分割と結合はエディタの操作で、T1-8で実装）：
  - 付けるのは、I302 の出る行（行IDを持てる行で、行IDも形の合わない候補も無い行）だけ。`status` が `ai-draft` のシーンの行にも付ける。E304 の行（形の合わない候補がある行）には付けない。
  - 付ける場所は、その行の末尾（改行の直前。行末の空白があれば、その後ろ）。` ^` と新しいIDを足すだけで、ほかの文字は変えない。複数行の台詞では、最後の行に付ける。
  - 新しいIDは6文字の乱数（`[0-9a-z]`）で作り、既存のIDと重ならないことを確かめる。既存のIDには、行IDを持てない行に付いたもの（W303）も含める。
  - `project.toml` の、本文の読み方に関わる設定を書かれたとおりに読めないときは、どの行にも付けない。台詞の括弧が既定に戻り、複数行の台詞の途中の行に付けてしまうことがあるため（16節、D042）。読み方に関わるのは、`project.toml` そのものを読めないとき（E801）、`format_version` の誤り（E802、E803）、`[dialogue]` と `[dialogue.brackets]` の誤り（E802）。`title`・`start_scene`・`[message_window]`・`[screen]`・`[editor]` の誤り（E802）では止めない（D045、D047、D050）。
  - 内容を編集しても、IDは変えない。
  - 行を分割したら前半が元のIDを引き継ぎ、後半に新しいIDを付ける。前半が行頭の字下げ（半角空白、タブ、段落頭の全角空白）だけのときは、中身のある後半が引き継ぐ。台詞の行（閉じ括弧が同じ行にあるもの）では、どこで改行しても閉じ括弧のある行が引き継ぐ。台詞の括弧の中での改行は、同じ台詞が複数行になるだけで、行IDは台詞の最後の行に付くため（6節。D046）。
  - 行を結合したら先頭の行のIDを残す。
  - 削除した行のIDは使い回さない（乱数の長さで、事実上起きないようにする）。

## 10. ディレクティブ

- 形は `@名前 引数1 引数2 …`。引数は半角または全角の空白で区切る。空白を含む引数は `"…"` で囲む。
- ただし `@選択`（問いかけ文）、`@設定`（代入）、`@if` と `@elif`（式）は、命令名の後ろの行の残り全体を1つの引数として読む。問いかけ文には `{w 0.5}` のような空白を含む記法を書ける。
- 日本語名と英語名は同じ命令の別名で、どちらで書いてもよい。制御の命令（`@if`、`@elif`、`@else`、`@raw`、`@end`）には日本語名を設けない。
- 命令名は下の表のとおりに書き、大文字と小文字を区別する（`@BGM` と `@bgm` は使えるが、`@Bgm` は W401）。
- ブロック（`@選択`、`@if`、`@raw`）は `@end` で閉じる。閉じていなければ E103 を出し、次のシーン見出し、またはファイルの終わりで閉じたものとみなす（`@raw` の中では、行頭に空白の無い `## ` の行だけをシーン見出しとみなす。15節）。

| --- | --- | --- | --- |
| `@背景` | `@bg` | 背景名 [トランジション] | `bg` |
| `@立ち絵` | `@show` | キャラ 差分 [位置] [トランジション] | `show` |
| `@退場` | `@hide` | キャラ [トランジション] | `hide` |

| `@待機` | `@wait` | 秒 | `wait` |
| `@設定` | `@set` | 変数 演算子 式（14節） | `set` |
| `@選択` | `@choice` | [問いかけ文]（ブロック、11節） | `choice` |
| `@if` | `@if` | 式（ブロック、12節） | `if` |
| `@elif` | `@elif` | 式 | |
| `@else` | `@else` | なし | |

- 引数のキーワードにも日英の別名がある。位置は `左` / `中` / `右`（`left` / `center` / `right`）、`@BGM` の停止は `停止`（`stop`）。命令名の言語と関係なく、どちらで書いてもよい。IRでは英語の値にそろえる。
- `@エンディング` のエンディングIDは、シーンIDと同じ文字（5節）で書く。形が合わなければ E111。
- `@立ち絵` の引数が3つのとき、3つ目が位置のキーワードでなければ、位置を省いたものとしてトランジションとして読む。引数が4つのときは、3つ目が位置のキーワードでなければ E402。
- 秒（`@効果` と `@待機`）は半角の数（`1`、`0.5`）で書く。数でなければ E402。
- 知らないディレクティブには W401 を出す（フェーズ1でマクロとして解決する可能性があるため、エラーにしない）。
- 引数の数が合わなければ E402。`"…"` の `"` が閉じていなければ、E402 を出してその行を無視する（`@raw` は、E402 を出したうえでブロックとして開く）。
- 素材カタログ（`assets/catalog.yaml`）と照合するのは、`@背景` の背景名、`@立ち絵` の差分（キャラクターごと）、`@BGM` の曲名、`@SE` と文中の `{se}` の効果音名だけ。カタログに無ければ I403 を出し、仮素材として扱う。トランジション（`フェード` など）と `@効果` の効果名は、カタログではなく出力プロファイルで解決するので照合しない。
- `@立ち絵` と `@退場` のキャラが解決できなければ W404。そのときは差分を照合しない（I403 を重ねない）。

## 11. 選択肢

```
@選択 どう答える ^k3fc
- 「ごめん、遅くなって」 ^k3fd
  @設定 灯.好感度 += 1
- 黙ってうなずく if 勇気 >= 2 ^k3fe
  灯「……そういうところ、ずるいよね」 ^k3ff
  -> s014
@end
```

- 選択ブロックは `@選択` で始まり `@end` で終わる。閉じていなければ E103。選択肢が1つも無ければ E106。
- `@選択` の行と最初の選択肢の行の間に置けるのは、空行とコメントだけ。ほかの行（`@end` を除く）には E402 を出して読み飛ばす。選択肢の無いまま `@end` が来たときは、E106 だけを出す。
- 選択肢の行は `- 表示文 [if 式] [-> シーンID] [^行ID]`。条件は括弧で囲まない。行の右から順に、行ID、最後の ` -> `、最後の ` if ` を切り出す。` if ` と ` -> ` の前の半角空白は、`-` の後の半角空白と兼ねてよい。表示文が空なら E402（`-` だけの行、`- -> s014`、`- if 勇気 >= 2`）。
- 表示文に半角の ` if ` や ` -> ` を含めると、最後のものが条件やジャンプとして切り出される（`- What if I said no` は、`I said no` を式として読んで E601 になる）。
- 選択肢の中身は、次の選択肢の行か `@end` までの行。中身にはどの種類の行も置ける。
- 選択肢の行に `-> シーンID` を書いたときは、中身を実行してから飛ぶ（中身の最後にジャンプを書いたのと同じ）。
- 中身にジャンプが無ければ、`@end` の次の行へ進む。
- 選択ブロックの中に選択ブロックを入れてよい。内側のブロックは、外側の次の選択肢より前に `@end` で閉じる。

## 12. 条件分岐

```
@if 灯.好感度 >= 3
  灯「やっぱり、君には言っておく」 ^k3fg
  -> s013a
@elif 勇気 >= 2
  -> s014
@else
  -> s013b
@end
```

- `@if`、`@elif`（任意、複数可）、`@else`（任意、1つ）、`@end` で1つのブロックにする。
- 対応の取れない `@elif`、`@else`、`@end` には E104。2つ目の `@else` と、`@else` の後の `@elif` も E104。

## 13. ジャンプ・呼び出し・シーンの終わり

- `-> シーンID` で、そのシーンへ移る。シーンIDはプロジェクト全体で一意なので、別ファイルのシーンへもそのまま飛べる。存在しないシーンなら E501。
- ジャンプ、`@エンディング`、`@戻る` の後ろで、同じ枝の中にある行は実行されないので W502 を出す。枝は、シーンの本文、選択肢の中身、`@if`・`@elif`・`@else` のそれぞれの中身を指す。枝を区切る行（`@end`、`@elif`、`@else`、次の選択肢の行）と、空行、コメントには W502 を出さない。
- W502 は、実行されない要素（行、またはブロック）ごとに1つ出す。ブロックには開きの行に1つだけ出し、その中の行には重ねない。
- `@呼出 シーンID` はそのシーンを実行し、`@戻る` で呼び出しの次の行へ戻る。
- **シーンの終わりでは、暗黙に次のシーンへ進まない**。一本道の章でも、次のシーンへ進むには `-> シーンID` を書く。「次のシーン」を表す省略記法は設けない。
- ジャンプ、`@エンディング`、`@戻る` のどれにも当たらずにシーンが終わる経路があれば、W503（行き止まり）を出す。

## 14. 式と変数

### 文法

```
式       := 論理和
論理和   := 論理積 ( "or" 論理積 )*
論理積   := 否定 ( "and" 否定 )*
否定     := "not" 否定 | 比較
比較     := 加減 ( ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) 加減 )?
加減     := 乗除 ( ( "+" | "-" ) 乗除 )*
乗除     := 単項 ( ( "*" | "/" ) 単項 )*
単項     := "-" 単項 | 基本
基本     := 整数 | 文字列 | "true" | "false" | 変数名 | "(" 式 ")"
変数名   := 名前 ( "." 名前 )?
名前     := ( 文字 | "_" ) ( 文字 | 数字 | "_" )*   // Unicodeの文字を含む。日本語の名前を使える
整数     := 半角の数字+
文字列   := '"' ( '\"' | '"'以外の文字 )* '"'
代入     := 変数名 ( "=" | "+=" | "-=" ) 式  // @設定 で使う
```

- 演算子と記号は半角で書く。`≥` などの記号は画面表示だけで使う。
- 式の中の空白（半角空白、タブ、全角空白）は、字句の区切りとして読む。
- 名前は数字で始められない（`1日目` は E601）。`and`、`or`、`not`、`true`、`false` は名前に使えない。
- 整数の割り算は切り捨てにする。

### 名前空間

- `.` の無い名前は `flag.` を補う（`勇気` は `flag.勇気`）。
- 名前空間がキャラクターのID・名前・呼び名に一致すれば、キャラクターIDにそろえる（`灯.好感度` も `あかり.好感度` も `akari.好感度`）。照合の順と、2人以上に一致したときの扱いは、台詞の話者と同じ（6節）。
- それ以外の名前空間（`周回` など）は書いたとおりに使う。

### 型と検査

- 型は真偽（`bool`）、整数（`int`）、文字列（`string`）、列挙（`enum`）。変数は `variables.yaml` で宣言する（`docs/design.md` の「変数と検証」）。
- 列挙の値は文字列で書く（`flag.ルート == "灯"`、`@設定 flag.ルート = "灯"`）。宣言の `values` に無い値は E603。
- 式の構文が崩れていれば E601、宣言されていない変数は W602、型が合わなければ E603、`+=` と `-=` を整数以外に使えば E604。
- 宣言されていない変数（W602）には型の検査をしない（E603・E604 を重ねない）。`variables.yaml` を丸ごと読めないとき（E801、または対応表でない E802）は、W602 を出さない（D042）。
- E604 を出したときは、代入の型の不一致としての E603 は重ねない（値の式の中の誤り、たとえば `1 + "a"` には E603 を出す）。
- 型の規則（どれかに合わなければ E603）：
  - `+`・`-`・`*`・`/`・単項の `-` と、`<`・`<=`・`>`・`>=` は、整数にだけ使える。
  - `and`・`or`・`not` と、条件（`@if`・`@elif`・選択肢の ` if `）は、真偽にだけ使える。
  - `==`・`!=` は、同じ型どうしで使う。
  - 列挙と比べたり、列挙の変数に代入したりできるのは、`values` にある値の文字列のリテラルか、同じ `values` を持つ列挙だけ。
  - 代入（`=`）の値は、変数と同じ型にする。`+=`・`-=` の値は整数にする。
  - 演算の結果の型は、演算子で決まる（`+` なら整数、比較なら真偽）。宣言されていない変数を含む演算でも同じ。

### 評価（プレビュー。T1-11、D050）

アプリのプレビューで式を評価するときの規則。静的な検査（上の型と検査）を通らない式も、止めずに評価する。

- 値は真偽・整数・文字列（列挙の値は文字列）。変数の初期値は `docs/spec/project-files.md` の3節。宣言されていない変数（W602）は、書かれるまで値が無い。
- 整数の割り算は0の向きへ切り捨てる（`-7 / 2` は `-3`）。0での割り算は誤り。
- `and`・`or` は左から評価し、左で決まれば右を評価しない。`==`・`!=` は型も比べる（型が違えば等しくない）。
- 誤り（値の無い変数を読む、型の合わない演算、0での割り算、構文の崩れた式 E601）を含む条件は偽として扱い、プレビューで知らせる。誤りのある `@設定` は書かない（`+=`・`-=` は、値の無い変数と整数でない変数には誤り。宣言された変数に、宣言の型に合わない値（列挙なら `values` に無い値）を書くのも誤り）。誤りのある変数の埋め込みは `{=式}` のまま見せる。
- 変数の埋め込みは、整数は10進、真偽は `true`・`false`、文字列はそのまま見せる。
- カーソル位置から再生（T2-4、D055）の最短経路（開始シーンから、選んだ選択肢の数がいちばん少ない道）も、この規則で式を評価し、命令を実行して求める。

## 15. 生コード

```
@raw renpy
  $ renpy.music.set_volume(0.6, channel="music")
@end
```

- `@raw` から `@end` までの行は解析せず、IRに渡す。中の行には4節の処理（行末の空白の除去、行IDの切り出し、行頭の空白の読み飛ばし、分類）を行わない。`## ` で始まる行や、` ^xxxx` で終わる行も、そのまま中身になる。
- 探すのは、前後の空白を除くと `@end` だけになる行（ブロックの終わり）だけ。
- それより前に、行頭に空白の無い `## ` で始まる行が来たら、`@end` を忘れたものとみなす。E103 を出してその行の手前で閉じ、その行はシーン見出しとして読む。`## ` で始まる行を中身に書くときは、字下げする。
- `@end` も、行頭に空白の無い `## ` の行も無いままファイルが終われば、E103 を出してファイルの終わりで閉じる。
- ブロック内の空でない行に共通する行頭の空白（半角空白とタブの並びとして、文字どおり共通な部分）だけを取り除き、それより深い字下げは保つ。半角空白とタブだけの行は空行とみなし、共通の字下げの計算から外して、空行として渡す。上の例では、IRに渡る行は `$ renpy.music.set_volume(0.6, channel="music")` になる。
- 字下げの深さを変えても（選択肢の中に移すなど）、IRに渡る行は変わらない。
- 指定したエンジンへの出力でだけ書き出し、それ以外の出力では読み飛ばす。

設定ファイル（`project.toml`、`variables.yaml`、`assets/catalog.yaml`、設定DB）の誤りでは解析を止めず、診断にして、読めた部分で続ける（D042）。

- 診断の `file` は、そのファイルのプロジェクトの根からの相対パス、`span` はそのファイルの中の位置（項目の位置が分からなければ先頭）。W804 の `file` はフォルダのパス。
- `project.toml` が無いフォルダは、プロジェクトではない（診断ではなく、読み込みのエラーにする）。構文が崩れていれば（E801）、既定の設定（`format_version` は0、開始シーンなし、括弧は「」）で読む。`[dialogue.brackets]` の合わない組（括弧が2文字でない、表示スタイルが英字でない、ほかの組と括弧が重なる）は読み飛ばし（E802）、1組も読めなければ既定の「」を使う。組はキーの文字コードの順（書いた順ではない）に読み、重なりは先に読んだ組を残す。`dialogue` が表でなければ E802 を出して既定の「」を使う。
- 読み飛ばす単位：`variables.yaml` は変数1つ、素材カタログは節（`backgrounds` など）か、キャラクター1人の差分か、文字列にできない意味名1つ、設定DBは型の項目の定義1つかエントリ1つ（キャラクターの `aliases` の誤りは、呼び名だけを読み飛ばす）。読み飛ばした変数への参照は、宣言されていない変数（W602）になる。
- `variables.yaml` を丸ごと読めなければ（E801、または対応表でない E802）、W602 を出さない（E801 を埋もれさせないため）。
- 変数の宣言の値が型に合わなければ（`default` の型、列挙の値、`range` の形・向き・型、`default` が `range` の外、`scope` が `save`・`persistent` でない）、W807 を出す。宣言は読み飛ばさない（T2-10、D061）。
- キャラクターは、型定義に `builtin: character` のある型のエントリ。そういう型が無ければ（型定義を読めないときも）、フォルダ名 `character` の型を使う。`builtin` に書けるのは `character` だけで、2つ以上の型に書いたときは最初の型を使う（E802）。
- 本文のファイル（`story/` の下の `*.scn`。下のフォルダも読む）がUTF-8でなければ、E801 を出して読み飛ばす。読めない下のフォルダ（権限が無いなど）も、E801 を出して中を読み飛ばす（位置はフォルダのパスの 0。T2-10、D061）。
- 設定ファイルの先頭の BOM（U+FEFF）は読み飛ばす（YAML の読み手が BOM の後ろを2つ目の文書と読んで E801 にしないように。T2-10、D061）。
- フロントマターの `id`・`name`・`aliases` の値は、文字列・数・真偽を受け付け、文字列にする。
- 型定義の項目の型が読めなければ（`txt` などの打ち間違い、閉じていない `list<`）、その項目の定義を読み飛ばす（E802）。エントリの値が項目の型に合わなければ W805 を出す（値は読み飛ばさない）。値の書き方と、W805 で調べない項目は `docs/spec/project-files.md` の5節（T1-10、D049）。
- `project.toml` の、本文の読み方に関わる設定（`format_version`、`[dialogue]`）にエラーがあるとき（`project.toml` そのものを読めないときを含む）は、台詞の括弧を書かれたとおりに読めないかもしれないので、行IDの付与（`scn fmt`、保存のとき）は何もしない（9節、D045）。

段階0の診断は、解析（構文解析・意味解析・IR）のたびに出る（IRの `diagnostics`）。段階1の診断は、プロジェクト全体の検証（`scn check`）で出す（IRの `diagnostics` には入らない）。

### 検証の段階1（`scn check`）

`docs/design.md` の検証項目の表の段階1を、IRと索引とプロジェクトの宣言から調べる（T1-4、D043）。条件は見ず、辺（ジャンプと呼び出し）だけをたどる。

- 行き止まり（W503）：ジャンプ・`@エンディング`・`@戻る` のどれにも当たらずにシーンが終わる経路がある（13節）。選択肢のブロックは、どの選択肢も出口（選択肢の行のジャンプか、中身の出口）を持つときだけ、`@if` は `@else` があり、どの枝も出口を持つときだけ、出口とみなす。`@呼出` は出口ではない。位置はシーン見出し。
- 到達できないシーン（W504）：開始シーンから、ジャンプと呼び出しの辺をたどって着けないシーン。開始シーンは `project.toml` の `start_scene`。無ければ、ファイルと行の順で最初のシーン。`start_scene` が存在しないシーンを指すときは、シーンが1つも無くても `project.toml` に E501 を出し、最初のシーンから数える。
- エンディングに着かないシーン（W505）：`@エンディング` を含むシーン、行き止まり（W503）のシーン、存在しないシーンへの辺（E501）を持つシーンのどれにも、ジャンプと呼び出しの辺をたどって着けないシーン（循環）。行き止まりに続くだけのシーンと、ジャンプの辺だけをたどって `@戻る` を含むシーンに着くシーン（呼ばれる側）には出さない。呼び出しを挟んだ循環（`@呼出` の後に自分へ戻る）は、呼ぶ側に出す。
- はみ出し（W203）：`project.toml` の `[message_window]`（`lines` 行×`chars_per_line` 字。どちらも正の整数）に、台詞と地の文が収まるか。無ければ調べない。表示する文字だけを数える：ルビは親文字、傍点は中身、インライン命令と変数の埋め込みは0。話者名と台詞の括弧は数えない。全角を1、半角（ASCIIの印字できる文字と半角カタカナ）を0.5と数える。`chars_per_line` 字で折り返し、複数行の台詞の改行で行を改め、`{p}` でページを改める。各ページの最初と最後の空の行は数えない（台詞の括弧だけの行や、`{p}` の直前と直後の改行は、何も表示しないため）。途中の空の行（改行が2つ続く）は1行に数える。どれかのページが `lines` 行を超えれば出す。禁則処理は考えない。台詞の形をした地の文（W202 など）は、書かれたとおりの文字を数える。
- 変数（W605・W606）：宣言された変数（`variables.yaml`）について、書く位置があって読む位置が無ければ W605、読む位置があって書く位置が無ければ W606。読む位置は、条件（`@if`・`@elif`・選択肢の条件）、変数の埋め込み、`@設定` の右辺。書く位置は `@設定`（`=`・`+=`・`-=`）。`scope: persistent` の変数（周回など、ゲームの側で書く想定）には W606 を出さない。読みも書きもしない変数には出さない。位置は `variables.yaml` の宣言。
- 企画書のエンディング（W701・W702）：企画書（`concept.md`）のフロントマターの `endings`（`id` を持つ対応表のリスト）と、本文の `@エンディング` のIDを照らす。企画書が無いか、`endings` が無ければ調べない。`endings` の形が合わない要素は E802 で読み飛ばす。W701 の位置は企画書のID、W702 の位置は `@エンディング` の行。
- 伏線（W703）：型 `foreshadow`（`bible/types/foreshadow.yaml`）のエントリの `payoff` が、無い・空・存在しないシーンを指すときに出す。`payoff` はシーンIDか、シーンIDのリスト。位置はエントリの `payoff` のキー（無ければファイルの先頭）。
- 参照切れ（W806）：設定DBのエントリの、型が `ref<型ID>`・`ref<scene>`・`list<ref<…>>` の項目の値が、無いエントリ（その型のフォルダに同じ `id` のエントリが無い。型の定義の無い型を指すときも、そのフォルダにエントリが無ければ出す）か、無いシーンを指すときに出す。リストは中身を1つずつ調べる。位置はエントリの項目のキー。伏線の `payoff` は W703 で調べるので出さない（T1-10、D049）。

### 検証の段階2（自動巡回。`scn check --stage 2`）

`docs/design.md` の検証項目の表の段階2のうち、実行して調べるものを、自動巡回で調べる（T3-2、D063）。重いので、`scn check` の既定（段階1）には入れず、`--stage 2` とアプリの検証の画面の「自動巡回」で走らせる。

- 実行の規則：開始シーンから、選べる選択肢の組み合わせをすべて実行する。式の評価と命令の実行は、カーソル位置から再生の最短経路とプレビューのランタイムと同じ（14節の「評価」、13節。誤りのある条件は偽、誤りのある `@設定` は書かない、宣言の無い変数は書かれるまで値が無い）。選択肢で分かれる状態（シーン、実行中のブロックと位置、`@呼出` の積み重ね、流れに関わる変数（条件で読む変数と、それを書く `@設定` で読む変数））が同じなら2度調べない。
- 永続の変数（`scope: persistent`）：宣言の初期値から始め、エンディングに着いたときの永続の変数の値の組から、もう一度始める（周回）。新しい組が出なくなるまで続ける。
- 上限：調べる状態は5万、周回の始め方は16通り、選択肢から次の選択肢までの命令は10万、`@呼出` の積み重ねの深さは64段（再帰する呼び出しのため）。超えたら調べるのをやめ、調べきれなかったことを結果に書く。そのときは、「無い」と言う診断（W506・W507・W509）は出さない（調べていない道で選べるかもしれないため）。見つけた事実（W508・W704）は出す。
- 決して選べない選択肢（W506）：その選択の行に着いたことがあり、選択肢の条件がどの状態でも真にならない。構文の崩れた条件（E601）には出さない。位置は選択肢の行。
- 決して真にならない条件（W507）：`@if`・`@elif` の条件が評価されたことがあり、どの状態でも真にならない。前の条件が真になって評価されない条件と、構文の崩れた条件（E601）には出さない。位置は `@if`・`@elif` の行。
- 選べる選択肢が無くなる選択（W508）：選択の行に着いたときに、選べる選択肢が1つも無い状態がある（そこで止まる）。位置は `@選択` の行。
- 着かないシーン（W509）：段階1の辺（ジャンプと呼び出し）では開始シーンから着けるのに、自動巡回で一度も入らないシーンのうち、自動巡回で入ったシーンからの辺の行き先になっているもの（条件の枝や選べない選択肢の先）。その先にしか無いシーンには出さない（原因は同じため）。位置はシーン見出し。
- 仕込みを通らない伏線（W704）：型 `foreshadow` のエントリの `setup`（シーンIDかそのリスト）のどれも通らずに、`payoff` のシーンに入る道がある。最初の始め方から周回もたどり、前の周で通った仕込みも通ったに数える。無いシーン（W703・W806）は除いて調べる。道の例（選んだ選択肢）を書く。位置はエントリの `payoff` のキー。
- 道の例：選択肢の表示文を、選ぶ順に並べる。周回をまたぐところには `〔周回〕` を入れる（前の周の道から書く）。
- 診断ではない結果：着いたシーンと選べた選択肢の数（カバレッジ）、エンディングごとの到達条件（着いたか、着いた状態の数、選択肢のいちばん少ない道の例、着いたときの流れに関わる変数の値（変数ごとに20個まで。書ききれなかった変数は `more` に））。調べきれなかったときに見つからなかったエンディングは、「着かない」ではなく「見つかっていない」と知らせる。`scn check --stage 2` は標準エラーに、`--json` では `playthrough` に出す（17節の外の形。`crates/scn-core/src/playthrough.rs` の `Playthrough`）。

## 17. IRの形

IRは、全機能（プレビュー、検証、エクスポート、AIの文脈）の共通の入力になる。T0-4で実装に合わせて決めた（D036）。形を変えたら `ir_version` を上げ、この節を更新する。

- JSONのフィールド名は `snake_case`。命令・文中の記法・式は、`kind` で種類を示す。
- `span` は `[開始, 終了]` の形の、UTF-8のバイト位置の範囲。そのシーンのファイルの先頭から数える（先頭のBOMも数に入れる）。
- 値が無いところは `null`（`line_id`、`transition` など）。リストが空なら `[]`。
- 診断（エラーを含む）があってもIRは作る。構文が崩れた部分の扱いは、各項目に書いた。

### 全体

| フィールド | 内容 |
| --- | --- |
| `ir_version` | IRの形のバージョン。今は `1` |
| `start_scene` | `project.toml` の `start_scene`。無ければ `null` |
| `scenes` | シーン。ファイルはパスの辞書順、ファイルの中は書かれた順 |
| `edges` | シーン間の辺 |
| `diagnostics` | 構文解析と意味解析の診断。ファイルの順、位置の順 |

### シーン

| フィールド | 内容 |
| --- | --- |
| `id` | シーンID。IDの無いシーン（W107・E111）は `_anon_<ファイル名>_<番号>`（5節）。重複したID（E108）も書かれたまま出す |
| `title` | 見出しのタイトル |
| `file` | プロジェクトの根からの相対パス（`story/chapter01.scn`、`story/part1/ch01.scn`）。読むのは `story/` の下（下のフォルダも）の `*.scn` で、隠しフォルダと隠しファイル（`.` で始まるもの）は読まない |
| `span` | 見出しの行 |
| `meta` | `summary`・`status`・`route`（文字列か `null`）、`tags`（文字列のリスト）、`extra`（知らないキーと、書かれたとおりの値の対応表） |
| `is_stub` | スタブ（本文に台詞・地の文が1つも無い。ブロックの中も見る）なら `true` |
| `ops` | 命令の並び |

- `status` の値が不正（E110）なら `null`。`tags` がリストでなければ、その値1つだけのリストにする（空なら `[]`）。

### 命令（`ops`）

どの命令も `kind` と `span`（その行。ブロックは開きの行）を持つ。

| `kind` | フィールド | 元の書き方 |
| --- | --- | --- |
| `say` | `line_id`、`speaker`（キャラクターID）、`display_name`、`style`（表示スタイル）、`text` | 話者を解決できた台詞 |
| `narrate` | `line_id`、`text` | 地の文。台詞の形でも地の文にしたもの（6節）は、話者・（表示名）・括弧・本文・閉じ括弧・後ろの文を書かれたとおりに並べる |
| `break` | なし | 本文に挟まれた空行（7節） |
| `bg` | `name`、`transition` | `@背景` |
| `show` | `character`、`expression`、`position`（`left`・`center`・`right`）、`transition` | `@立ち絵` |
| `hide` | `character`、`transition` | `@退場` |
| `bgm` | `name` | `@BGM` |
| `bgm_stop` | なし | `@BGM 停止` |
| `se` | `name` | `@SE` |
| `fx` | `name`、`seconds` | `@効果` |
| `wait` | `seconds` | `@待機` |
| `set` | `var`（そろえた変数名）、`op`（`=`・`+=`・`-=`）、`value`（式） | `@設定`。構文が崩れていれば（E601）出さない |
| `choice` | `line_id`、`prompt`（文か `null`）、`options` | `@選択` のブロック |
| `if` | `branches`、`else`（命令の並びか `null`） | `@if` のブロック |
| `jump` | `target` | `-> シーンID` |
| `call` | `target` | `@呼出` |
| `return` | なし | `@戻る` |
| `ending` | `id`（形が合わなければ `null`、E111） | `@エンディング` |
| `raw` | `engine`、`lines`（共通の字下げを取り除いた行） | `@raw` のブロック |
| `unknown_directive` | `name`（書かれた命令名）、`args` | 知らないディレクティブ（W401） |

- `character` はキャラクターID。解決できなければ（W404）書かれた名前のまま。
- 選択肢（`options` の各要素）：`span`、`line_id`、`text`、`cond_text`（書かれた条件。無ければ `null`）、`cond`（式。構文が崩れていれば `null`）、`jump`（選択肢の行の `-> シーンID`。中身を実行してから飛ぶ）、`body`（命令の並び）。
- 条件分岐の枝（`branches` の各要素）：`span`、`cond_text`、`cond`、`body`。最初の要素が `@if`、続く要素が `@elif`。

### 文中の記法（`text`、`prompt`）

| `kind` | フィールド | 元の書き方 |
| --- | --- | --- |
| `text` | `text` | ただの文字（`{{`・`}}`・`\|《` は `{`・`}`・`《` にしてある） |
| `ruby` | `base`、`reading` | ルビ |
| `emphasis` | `text` | 傍点 |
| `wait` | `seconds` | `{w 秒}` |
| `page_break` | なし | `{p}` |
| `se` | `name` | `{se 名前}` |
| `speed` | `speed`（`slow`・`normal`・`fast`） | `{speed 遅}` など |
| `interpolation` | `expr_text`（書かれた式）、`expr`（式か `null`） | `{=式}` |
| `line_break` | なし | 複数行の台詞の、行の境目（6節） |

### 式（`value`、`cond`、`expr`）

| `kind` | フィールド |
| --- | --- |
| `int` | `value`（整数） |
| `string` | `value`（文字列） |
| `bool` | `value`（真偽） |
| `var` | `name`（そろえた変数名。`灯.好感度` は `akari.好感度`、`勇気` は `flag.勇気`） |
| `unary` | `op`（`-`・`not`）、`operand` |
| `binary` | `op`（`or`・`and`・`==`・`!=`・`<`・`<=`・`>`・`>=`・`+`・`-`・`*`・`/`）、`lhs`、`rhs` |

### 辺（`edges`）

ジャンプ（`-> シーンID`、選択肢の行の `-> シーンID`）と `@呼出` ごとに1本。書かれた順に並べる。

| フィールド | 内容 |
| --- | --- |
| `from` | ジャンプを書いたシーンのID |
| `to` | 飛ぶ先のシーンID。存在しないシーン（E501）でも、書かれたとおりに出す |
| `kind` | `jump` か `call` |
| `via` | いちばん内側の文脈：`direct`（シーンの本文）、`choice`（選択肢の行か、その中身）、`if`（`@if`・`@elif` の中身）、`else`（`@else` の中身） |
| `label` | `via` が `choice` のとき、選択肢の表示文（ルビは親文字、傍点は文字だけ、変数の埋め込みは `{=式}` のまま、ほかの命令は除く）。それ以外は `null` |
| `cond_text` | 選択肢の条件、または `@if`・`@elif` の式（書かれたとおり）。無ければ `null` |
| `span` | ジャンプや呼び出しを書いた位置（`from` のシーンのファイル） |

### 診断（`diagnostics`）

| フィールド | 内容 |
| --- | --- |
| `code` | 診断コード（16節） |
| `severity` | `error`・`warning`・`info` |
| `file` | ファイルの相対パス |
| `span` | 位置 |
| `message` | メッセージ（日本語） |

読み込みの診断（E801〜W805）を先に読んだ順に並べ、続けて本文の診断を、ファイルと位置の順に並べる。

### 例

サンプル作品の `s012` の一部（位置の値は省いた）。サンプル全体のIRは `crates/scn-core/tests/snapshots/analyze__sample_houkago.snap` にある。

```json
{
  "ir_version": 1,
  "start_scene": "s010",
  "scenes": [
    {
      "id": "s012",
      "title": "放課後の屋上",
      "file": "story/chapter01.scn",
```

### 索引

索引は、IRとプロジェクトの宣言（設定DB、`variables.yaml`、素材カタログ）から導く一覧で、エディタの補完、設定DBの逆引き、検証が使う（T1-3、D042）。保存はせず、解析のたびに作り直す。位置は行の単位（命令、台詞、選択肢などのスパン）で持つ。形を変えたら `index_version` を上げ、この節を更新する。

| フィールド | 内容 |
| --- | --- |
| `index_version` | 索引の形のバージョン（今は1） |
| `scenes` | シーン（IRの順）：`id`、`title`、`file`、`span`（見出しの行）、`route`、`status`、`is_stub` |
| `characters` | 設定DBのキャラクター（IDの順）：`id`、`name`、`aliases`、`uses`（本文の順。`kind` は `speaker`・`show`・`hide`） |
| `variables` | 宣言された変数と、宣言されずに使われた変数（名前の順）：`key`（そろえた名前）、`declared`、`type`、`values`（列挙の値）、`reads`、`writes` |
| `assets` | カタログに登録された意味名と、登録されずに使われた意味名（種類・キャラクター・名前の順）：`kind`（`background`・`expression`・`bgm`・`se`）、`character`（差分のキャラクター）、`name`、`registered`、`uses` |
| `line_ids` | 行ID（本文に現れる順。重複していれば、それぞれを並べる）：`id` と位置 |

- 位置（`uses`、`reads`、`writes` の要素と、`line_ids` の要素）は、`scene`（シーンID）、`file`、`span`。
- 読む位置：`@if`・`@elif`・選択肢の条件、変数の埋め込み、`@設定` の右辺。同じ行で何度読んでも1つにする。書く位置：`@設定`（`=`・`+=`・`-=`）。`+=` は書く位置にだけ数える。
- 素材の位置：`@背景`（`background`）、`@立ち絵` の差分（`expression`）、`@BGM`（`bgm`。`停止` は除く）、`@SE` と文中の `{se}`（`se`）。
