# .scn 形式仕様 v0（ドラフト）

状態：ドラフト。フェーズ0のT0-2で「18. 未決事項」を決め、v0として確定する。確定までは、この文書の「現案」を前提に実装してよい。

この仕様は、`.scn` ファイルの書き方と、パーサが返す結果（AST・IR・診断）の約束を定める。プロジェクト全体の設計は `docs/design.md`、用語は `docs/glossary.md` を参照。

## 1. 基本方針

- 1行が1つの要素になる、行指向の形式にする。日本語の原稿として読めることと、機械が曖昧なく読めることを両立させる。
- 演出は意味名で書く（`@背景 屋上/夕方`）。ファイル名やエンジンの命令は書かない。
- パーサはエラー回復を行う。誤りは診断として返し、残りの解析は続ける。

## 2. ファイル

- 拡張子は `.scn`。文字コードはUTF-8。先頭のBOMは読み飛ばし、書き出すときは付けない。
- 改行はLFとCRLFの両方を受け付ける。保存するときは、元のファイルの改行を保つ。
- 1ファイルを1章として使うことを想定する。1ファイルに複数のシーンを置ける。
- 形式のバージョンは、プロジェクトの `project.toml` の `format_version` で1つだけ持つ。

## 3. ファイルの構造

```
[章見出し]           # 第1章 放課後
シーン*
シーン = シーン見出し [メタ情報ブロック] 本文行*
```

- 章見出し（`# ` で始まる行）は任意で、ファイルの先頭（空行とコメントを除く）に1つだけ置ける。
- 最初のシーン見出しより前に、章見出し・空行・コメント以外の行があれば W101 を出し、その行は無視する。

## 4. 行の分類

各行は、次の順で処理してから分類する。

1. 行末の行ID（` ^xxxx`、9節）を切り出す。
2. 行頭の半角空白とタブを読み飛ばす。これは見た目の整形用で、意味を持たない。全角空白（U+3000）は読み飛ばさず、本文の一部として扱う。
3. 行頭が `\` なら、次の1文字を記号として扱わず、その行を地の文として分類する（`\@`、`\-`、`\/`、`\#`、`\\`）。

分類は上から順に判定し、最初に当てはまったものに決める。

| 順 | 条件 | 種類 |
| --- | --- | --- |
| 1 | 何も残らない | 空行 |
| 2 | `//` で始まる | コメント |
| 3 | `# ` で始まり、ファイルの先頭にある | 章見出し |
| 4 | `## ` で始まる | シーン見出し |
| 5 | `---` だけで、シーン見出しの直後にある（またはメタ情報ブロックの中にある） | メタ情報の区切り |
| 6 | `@` で始まる | ディレクティブ |
| 7 | `- ` で始まる | 選択肢（選択ブロックの外なら E105 を出し、地の文として扱う） |
| 8 | `->` で始まる | ジャンプ |
| 9 | 台詞の形に当てはまる（6節） | 台詞候補 |
| 10 | 上のどれでもない | 地の文 |

## 5. シーン見出しとメタ情報

```
## 放課後の屋上 #s012
---
summary: 灯が転校を打ち明けかける
status: draft
route: 共通
tags: [屋上, 転校]
---
```

- 見出しは `## タイトル #シーンID`。行末の ` #` 以降がシーンIDで、それより前がタイトルになる。
- シーンIDは英数字と `_` で書く（現案、未決事項4）。プロジェクト全体で一意にする。重複したら、後から現れたほうに E108 を出す。ファイルはパスの辞書順、ファイル内は行の順で比べる。
- IDが無い見出しには W107 を出す。IRでは仮のID（`_anon_<ファイル名>_<番号>`）を付けるが、ジャンプ先には指定できない。IDはフェーズ1の整形コマンドで付ける。
- メタ情報ブロックは任意。見出しの次の行が `---` のときだけ始まり、次の `---` で終わる。閉じていなければ E102 を出し、次の空行までをメタ情報とみなして回復する。
- 中身はYAMLの一部（`キー: 値`、値は文字列か `[a, b]` 形式のリスト）だけを受け付ける。

| キー | 値 | 意味 |
| --- | --- | --- |
| `summary` | 文字列 | 要約。プロットカードに表示する |
| `status` | `draft` / `writing` / `done` / `ai-draft` | 状態。それ以外の値は E110 |
| `route` | 文字列 | ルート名。フロー図のグループ分けに使う |
| `tags` | リスト | 自由なタグ |

- 上の表に無いキーは I109 を出したうえで、文字列としてIRに渡す。
- **スタブ**は、本文に台詞・地の文が1行も無いシーンを指す。状態の値ではなく、内容から決まる。

## 6. 台詞

```
灯「やっと来た。遅いよ」 ^k3f9
灯（？？？）「誰？」
灯『……言えるわけないよ』
```

- 形は `話者「本文」`。表示名を上書きするときは `話者（表示名）「本文」` と書く。括弧は全角の（）。
- 使える括弧の種類と表示スタイル（通常、心の声など）は、`project.toml` の `[dialogue.brackets]` で決める。既定は「」だけ。

### 台詞の判定

判定は2段階で行う。

1. **構文解析**：行頭から、空白と括弧を含まない文字が1〜20文字続き、その後に任意で（表示名）、その後に登録済みの開き括弧が来れば、**台詞候補**とする。この段階では設定DBを見ない。
2. **意味解析**：話者を、キャラクターのID・名前・呼び名のどれかに解決する。
   - 解決できれば台詞にする。IRでの話者はキャラクターIDにする。
   - 解決できず、行全体が閉じ括弧で終わる場合は、W202 を出して地の文として扱う。
   - 解決できず、閉じ括弧の後に文が続く場合（`彼は「行こう」と言った。`）は、診断を出さずに地の文として扱う。

### 複数行にまたがる台詞

- 閉じ括弧が同じ行に無いときは、次の行以降を続きとして読み、閉じ括弧のある行で終える。行IDはその最後の行の末尾に付ける。
- 閉じる前に空行、シーン見出し、ディレクティブが来たら E201 を出し、その直前で台詞を終えて回復する。
- 本文の中の同じ種類の括弧は、入れ子として数える。

## 7. 地の文と空行

- 地の文は、行頭の全角空白（字下げ）も含めてそのまま本文にする。
- 空行は段落の区切りとする（現案、未決事項9）。IRでは、本文の行と行の間にある空行を `break` にまとめる（連続する空行は1つにする）。

## 8. 文中の記法

台詞の本文、地の文、選択肢の表示文、`@選択` の問いかけ文で使える。

| 記法 | 書き方 | 備考 |
| --- | --- | --- |
| ルビ | `\|親文字《るび》` または `｜親文字《るび》` | 小説投稿サイトと同じ |
| 自動ルビ | `漢字《かんじ》` | 直前に続く漢字（`々〆ヵヶ` を含む）を親文字にする |
| 《 そのもの | `\|《` | ルビにしない |
| 傍点 | `《《強調》》` | |
| ウェイト | `{w 0.5}` | 秒 |
| 改ページ | `{p}` | |
| 文中の効果音 | `{se ドア}` | 意味名 |
| 文字速度 | `{speed 遅}` | `遅` / `普通` / `速` |
| 変数の埋め込み | `{=湊.名前}` | 中身は式（14節） |
| 波括弧そのもの | `{{` と `}}` | |

- 知らないインライン命令には W405 を出し、そのまま文字として扱う。
- 閉じていない `{` は文字として扱う。

## 9. 行ID

```
灯「やっと来た。遅いよ」 ^k3f9
```

- 形は、1つ以上の半角空白に続く `^` と、`[0-9a-z]` の4〜12文字（現案、未決事項8）。形が崩れていれば E304。
- 行IDを持てるのは、台詞（複数行なら最後の行）、地の文、`@選択` の行、選択肢の行だけ。それ以外の行に付いていれば W303 を出して無視する。
- プロジェクト全体で一意にする。重複したら、後から現れたほうに E301 を出す。
- 行IDの無い台詞・地の文・選択肢には I302 を出す。**パーサは行IDを付けない**。付与はフェーズ1の整形コマンド（`scn fmt`）とエディタが行う。
- 付与のきまり（フェーズ1で実装）：
  - 新しいIDは6文字の乱数で作り、既存のIDと重ならないことを確かめる。
  - 内容を編集しても、IDは変えない。
  - 行を分割したら前半が元のIDを引き継ぎ、後半に新しいIDを付ける。
  - 行を結合したら先頭の行のIDを残す。
  - 削除した行のIDは使い回さない（乱数の長さで、事実上起きないようにする）。

## 10. ディレクティブ

- 形は `@名前 引数1 引数2 …`。引数は半角または全角の空白で区切る。空白を含む引数は `"…"` で囲む。
- 日本語名と英語名は同じ命令の別名で、どちらで書いてもよい。

| 日本語名 | 英語名 | 引数 | IR |
| --- | --- | --- | --- |
| `@背景` | `@bg` | 背景名 [トランジション] | `bg` |
| `@立ち絵` | `@show` | キャラ 差分 [位置] [トランジション] | `show` |
| `@退場` | `@hide` | キャラ [トランジション] | `hide` |
| `@BGM` | `@bgm` | 曲名、または `停止` | `bgm` / `bgm_stop` |
| `@SE` | `@se` | 効果音名 | `se` |
| `@効果` | `@fx` | 効果名 [秒] | `fx` |
| `@待機` | `@wait` | 秒 | `wait` |
| `@設定` | `@set` | 変数 演算子 式（14節） | `set` |
| `@選択` | `@choice` | [問いかけ文]（ブロック、11節） | `choice` |
| `@if` | `@if` | 式（ブロック、12節） | `if` |
| `@elif` | `@elif` | 式 | |
| `@else` | `@else` | なし | |
| `@呼出` | `@call` | シーンID | `call` |
| `@戻る` | `@return` | なし | `return` |
| `@エンディング` | `@ending` | エンディングID | `ending` |
| `@raw` | `@raw` | エンジン名（ブロック、15節） | `raw` |
| `@end` | `@end` | なし（ブロックを閉じる） | |

- 位置は `左` / `中` / `右`（`left` / `center` / `right`）。IRでは英語の値にそろえる。
- 知らないディレクティブには W401 を出す（フェーズ1でマクロとして解決する可能性があるため、エラーにしない）。
- 引数の数が合わなければ E402。
- 素材の意味名が素材カタログに無ければ I403（仮素材として扱う）。`@立ち絵` と `@退場` のキャラが解決できなければ W404。

## 11. 選択肢

```
@選択 どう答える ^k3fc
- 「ごめん、遅くなって」 ^k3fd
  @設定 灯.好感度 += 1
- 黙ってうなずく if 勇気 >= 2 ^k3fe
  灯「……そういうところ、ずるいよね」 ^k3ff
  -> s014
@end
```

- 選択ブロックは `@選択` で始まり `@end` で終わる。閉じていなければ E103。選択肢が1つも無ければ E106。
- 選択肢の行は `- 表示文 [if 式] [-> シーンID] [^行ID]`。行の右から順に、行ID、最後の ` -> `、最後の ` if ` を切り出す（現案、未決事項1）。表示文が空なら E402。
- 選択肢の中身は、次の選択肢の行か `@end` までの行。中身にはどの種類の行も置ける。
- 中身にジャンプが無ければ、`@end` の次の行へ進む。
- 選択ブロックの中に選択ブロックを入れてよい。内側のブロックは、外側の次の選択肢より前に `@end` で閉じる。

## 12. 条件分岐

```
@if 灯.好感度 >= 3
  灯「やっぱり、君には言っておく」 ^k3fg
  -> s013a
@elif 勇気 >= 2
  -> s014
@else
  -> s013b
@end
```

- `@if`、`@elif`（任意、複数可）、`@else`（任意、1つ）、`@end` で1つのブロックにする。
- 対応の取れない `@elif`、`@else`、`@end` には E104。

## 13. ジャンプ・呼び出し・シーンの終わり

- `-> シーンID` で、そのシーンへ移る。シーンIDはプロジェクト全体で一意なので、別ファイルのシーンへもそのまま飛べる。存在しないシーンなら E501。
- ジャンプの後ろで、同じブロックの中にある行は実行されないので W502 を出す。
- `@呼出 シーンID` はそのシーンを実行し、`@戻る` で呼び出しの次の行へ戻る。
- **シーンの終わりでは、暗黙に次のシーンへ進まない**（現案、未決事項2）。ジャンプ、`@エンディング`、`@戻る` のどれにも当たらずにシーンが終わる経路があれば、W503（行き止まり）を出す。

## 14. 式と変数

### 文法

```
式       := 論理和
論理和   := 論理積 ( "or" 論理積 )*
論理積   := 否定 ( "and" 否定 )*
否定     := "not" 否定 | 比較
比較     := 加減 ( ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) 加減 )?
加減     := 乗除 ( ( "+" | "-" ) 乗除 )*
乗除     := 単項 ( ( "*" | "/" ) 単項 )*
単項     := "-" 単項 | 基本
基本     := 整数 | 文字列 | "true" | "false" | 変数名 | "(" 式 ")"
変数名   := 名前 ( "." 名前 )?
名前     := ( 文字 | 数字 | "_" )+        // Unicodeの文字を含む。日本語の名前を使える
文字列   := '"' ( '\"' | '"'以外の文字 )* '"'
代入     := 変数名 ( "=" | "+=" | "-=" ) 式  // @設定 で使う
```

- 演算子と記号は半角で書く。`≥` などの記号は画面表示だけで使う。
- 整数の割り算は切り捨てにする。

### 名前空間

- `.` の無い名前は `flag.` を補う（`勇気` は `flag.勇気`）。
- 名前空間がキャラクターのID・名前・呼び名に一致すれば、キャラクターIDにそろえる（`灯.好感度` は `akari.好感度`）。現案、未決事項5。
- それ以外の名前空間（`周回` など）は書いたとおりに使う。

### 型と検査

- 型は真偽（`bool`）、整数（`int`）、文字列（`string`）、列挙（`enum`）。変数は `variables.yaml` で宣言する（`docs/design.md` の「変数と検証」）。
- 列挙の値は文字列で書く（`flag.ルート == "灯"`）。現案、未決事項6。
- 式の構文が崩れていれば E601、宣言されていない変数は W602、型が合わなければ E603、`+=` と `-=` を整数以外に使えば E604。

## 15. 生コード

```
@raw renpy
  $ renpy.music.set_volume(0.6, channel="music")
@end
```

- `@raw` から `@end` までの行は解析せず、そのままIRに渡す（行頭の空白も保つ。未決事項10）。
- 指定したエンジンへの出力でだけ書き出し、それ以外の出力では読み飛ばす。

## 16. 診断の一覧（初期案）

重大度は E（エラー）、W（警告）、I（情報）。「段階」は実装するフェーズ。フェーズ0で実装するのは段階0の診断。

| コード | 重大度 | 内容 | 段階 |
| --- | --- | --- | --- |
| W101 | 警告 | 最初のシーンより前に本文がある | 0 |
| E102 | エラー | メタ情報の `---` が閉じていない | 0 |
| E103 | エラー | ブロック（`@選択`・`@if`・`@raw`）が `@end` で閉じていない | 0 |
| E104 | エラー | 対応するブロックの無い `@elif`・`@else`・`@end` | 0 |
| E105 | エラー | 選択ブロックの外にある選択肢の行 | 0 |
| E106 | エラー | 選択肢が1つも無い `@選択` | 0 |
| W107 | 警告 | シーン見出しにIDが無い | 0 |
| E108 | エラー | シーンIDの重複 | 0 |
| I109 | 情報 | 知らないメタ情報のキー | 0 |
| E110 | エラー | `status` の値が不正 | 0 |
| E201 | エラー | 台詞の閉じ括弧が無い | 0 |
| W202 | 警告 | 台詞の形だが、話者を解決できない（地の文として扱う） | 0 |
| E301 | エラー | 行IDの重複 | 0 |
| I302 | 情報 | 行IDが無い | 0 |
| W303 | 警告 | 行IDを持てない行に行IDがある | 0 |
| E304 | エラー | 行IDの形が不正 | 0 |
| W401 | 警告 | 知らないディレクティブ | 0 |
| E402 | エラー | ディレクティブの引数の数、または選択肢の形が合わない | 0 |
| I403 | 情報 | 素材カタログに無い意味名（仮素材） | 0 |
| W404 | 警告 | `@立ち絵`・`@退場` のキャラを解決できない | 0 |
| W405 | 警告 | 知らないインライン命令 | 0 |
| E501 | エラー | 存在しないシーンへのジャンプ・呼び出し | 0 |
| W502 | 警告 | ジャンプの後にある、実行されない行 | 0 |
| W503 | 警告 | 行き止まり（シーンの終わりに出口が無い経路がある） | 1 |
| E601 | エラー | 式の構文エラー | 0 |
| W602 | 警告 | 宣言されていない変数 | 0 |
| E603 | エラー | 型の不一致 | 0 |
| E604 | エラー | `+=`・`-=` を整数以外に使った | 0 |
| W701 | 警告 | 企画書のエンディングが本文に無い | 1 |
| W702 | 警告 | 本文のエンディングが企画書に無い | 1 |

到達性、未使用の変数、伏線、メッセージウィンドウのはみ出しなど、プロジェクト全体の検証はフェーズ1の `scn check` で扱う（`docs/design.md` の検証項目の表）。コードは上の表の続きで割り当てる。

## 17. IRの形（初期案）

IRは、全機能（プレビュー、検証、エクスポート、AIの文脈）の共通の入力になる。T0-4で形を決め、この節を更新する。

```json
      "is_stub": false,

  ],
  "edges": [
    { "from": "s012", "to": "s013a", "via": "if", "cond_text": "灯.好感度 >= 3" }
  ],
  "diagnostics": [
    { "code": "I302", "severity": "info", "file": "story/chapter01.scn", "span": [1024, 1050], "message": "行IDがありません" }
  ]
}
```

- 各命令は元の位置（`span`、UTF-8のバイト位置）を持つ。上の例では省略している。
- 式は、IRでは木の形で持つ。`edges` の `cond_text` は表示用の文字列。

## 18. 未決事項（T0-2で決める）

| 番号 | 論点 | 現案 |
| --- | --- | --- |

| 3 | 章見出し `# ` | ファイル先頭に任意で1つ |
| 4 | シーンIDの文字 | 英数字と `_` だけ。日本語を許すかを決める |
| 5 | 変数の名前空間にキャラの名前を使えるか | 使える。正規形はキャラクターID |
| 6 | 列挙の値の書き方 | 文字列（`"灯"`） |
| 7 | 台詞候補の話者名の長さと、未登録話者の扱い | 1〜20文字。行全体が括弧で閉じるときだけ W202 |
