# .scn 形式仕様 v0

状態：v0確定（2026-10-07）。未決事項はT0-2ですべて決めた（経緯は `docs/decisions.md` の D016〜D034）。「17. IRの形」だけは、T0-4で実装に合わせて更新する。

この仕様は、`.scn` ファイルの書き方と、パーサが返す結果（AST・IR・診断）の約束を定める。プロジェクト全体の設計は `docs/design.md`、用語は `docs/glossary.md` を参照。

## 1. 基本方針

- 1行が1つの要素になる、行指向の形式にする。日本語の原稿として読めることと、機械が曖昧なく読めることを両立させる。
- 演出は意味名で書く（`@背景 屋上/夕方`）。ファイル名やエンジンの命令は書かない。
- パーサはエラー回復を行う。誤りは診断として返し、残りの解析は続ける。

## 2. ファイル

- 拡張子は `.scn`。文字コードはUTF-8。先頭のBOMは読み飛ばし、書き出すときは付けない。
- 改行はLFとCRLFの両方を受け付ける。保存するときは、元のファイルの改行を保つ。
- 1ファイルを1章として使うことを想定する。1ファイルに複数のシーンを置ける。
- 形式のバージョンは、プロジェクトの `project.toml` の `format_version` で1つだけ持つ。

## 3. ファイルの構造

```
[章見出し]           # 第1章 放課後
シーン*
シーン = シーン見出し [メタ情報ブロック] 本文行*
```

- 章見出し（`# ` で始まる行）は任意で、ファイルの先頭（空行とコメントを除く）に1つだけ置ける。
- ファイルの先頭以外にある `# ` の行は、章見出しにならない。W112 を出し、地の文として扱う。
- 最初のシーン見出しより前に、章見出し・空行・コメント以外の行があれば W101 を出し、その行は無視する（先頭以外の `# ` の行がシーンより前にあれば、W112 と W101 の両方を出す）。

## 4. 行の分類

各行は、次の順で処理してから分類する（`@raw` ブロックの中の行は除く。15節）。

1. 行末の半角空白とタブを取り除く。行頭と同じく見た目の整形用として扱い、行IDの切り出しより前に行う（行IDの後ろに見えない空白があっても、行IDとして読む）。全角空白は取り除かない。
2. 行頭の半角空白とタブを読み飛ばした残りが `//` で始まる行は、コメントとし、ここで処理を終える。コメントの行からは行IDを切り出さない（行をコメントアウトしたときに、W303 や E304 を出さない）。
3. 行末の行ID（` ^xxxx`、9節）を切り出す。
4. 行頭の半角空白とタブを読み飛ばす。これは見た目の整形用で、意味を持たない。全角空白（U+3000）は読み飛ばさず、本文の一部として扱う。
5. 行頭が `\` なら、その `\` を取り除き、残りを地の文として分類する。続く文字は何でもよい。記号（`\@`、`\-`、`\/`、`\#`、`\\`）を本文として書くときや、台詞の形をした地の文（`\窓の外から「おーい」`）を書くときに使う。`\` で始まる地の文は `\\` と書く。

分類は上から順に判定し、最初に当てはまったものに決める。

| 順 | 条件 | 種類 |
| --- | --- | --- |
| 1 | 何も残らない | 空行 |
| 2 | `//` で始まる | コメント |
| 3 | `# ` で始まり、ファイルの先頭にある | 章見出し |
| 4 | `## ` で始まる | シーン見出し |
| 5 | `---` だけで、シーン見出しの直後にある（またはメタ情報ブロックの中にある） | メタ情報の区切り |
| 6 | `@` で始まる | ディレクティブ |
| 7 | `-` の後に半角空白が続くか、`-` だけ | 選択肢（選択ブロックの外なら E105 を出し、地の文として扱う） |
| 8 | `->` で始まる | ジャンプ |
| 9 | 台詞の形に当てはまる（6節） | 台詞候補 |
| 10 | 上のどれでもない | 地の文 |

- 3の条件に当てはまらない `# ` の行（ファイルの先頭に無いもの）は、10の地の文になる（3節、W112）。
- 空白は、半角空白、タブ、全角空白（U+3000）を指す。ただし行頭で読み飛ばすのと行末で取り除くのは、半角空白とタブだけ（上の1と4）。

## 5. シーン見出しとメタ情報

```
## 放課後の屋上 #s012
---
summary: 灯が転校を打ち明けかける
status: draft
route: 共通
tags: [屋上, 転校]
---
```

- 見出しは `## タイトル #シーンID`。行末の最後の ` #` 以降がシーンIDで、それより前がタイトルになる。
- シーンIDは英数字（`A-Z`、`a-z`、`0-9`）と `_` で、1文字以上書く。大文字と小文字は区別する。プロジェクト全体で一意にする。重複したら、後から現れたほうに E108 を出す。ファイルはパスの辞書順、ファイル内は行の順で比べる。
- ` #` 以降が上の形に合わなければ（`#帰り道`、`#s-1`、` #` の後が空）、E111 を出し、IDの無い見出しとして扱う（W107 は出さない）。タイトルは、最後の ` #` より前の部分にする。
- ` #` の無い見出しには W107 を出す。IRでは仮のID（`_anon_<ファイル名>_<番号>`）を付けるが、ジャンプ先には指定できない。IDはフェーズ1の整形コマンドで付ける。
- メタ情報ブロックは任意。見出しの次の行が `---` のときだけ始まり、次の `---` で終わる。閉じの `---` は、次のシーン見出しより前（無ければファイルの終わりまで）でだけ探し、その範囲に無ければ閉じていないものとする。シーン見出しは、メタ情報の中でも見出しとして読む。
- 中身はYAMLの一部（`キー: 値`、値は文字列か `[a, b]` 形式のリスト）だけを受け付ける。キーは空白と `:` を含まない1文字以上で、`:` の後は半角空白か行末。
- 閉じたブロックの中では、空行とコメントの行は読み飛ばし、`キー: 値` の形でない行には E114 を出して読み飛ばす。
- 閉じていなければ E102 を出し、`---` の次の行から `キー: 値` の形の行が続く間だけをメタ情報とみなして回復する（コメントの行は読み飛ばす。空行やシーン見出しなど、形の違う行が来たら終える）。
- 同じキーが2回以上あれば、後の値を使い、W113 を出す。

| キー | 値 | 意味 |
| --- | --- | --- |
| `summary` | 文字列 | 要約。プロットカードに表示する |
| `status` | `draft` / `writing` / `done` / `ai-draft` | 状態。それ以外の値は E110 |
| `route` | 文字列 | ルート名。フロー図のグループ分けに使う |
| `tags` | リスト | 自由なタグ |

- 上の表に無いキーは I109 を出したうえで、文字列としてIRに渡す。
- **スタブ**は、本文に台詞・地の文が1行も無いシーンを指す。状態の値ではなく、内容から決まる。

## 6. 台詞

```
灯「やっと来た。遅いよ」 ^k3f9
灯（？？？）「誰？」
灯『……言えるわけないよ』
```

- 形は `話者「本文」`。表示名を上書きするときは `話者（表示名）「本文」` と書く。表示名の括弧は全角の（）。表示名は空でもよい（`灯（）「……」`。名前を出さずに表示するときに使う）。

### 括弧と表示スタイル

```toml
[dialogue.brackets]
"「」" = "normal"
"『』" = "thought"   # 心の声
```

- 台詞に使える括弧の種類と表示スタイルは、`project.toml` の `[dialogue.brackets]` で決める。キーは開き括弧と閉じ括弧の2文字（互いに違う文字）、値は表示スタイルの名前（`normal`、`thought` などの英字の名前）。
- この節を書くと、その一覧が既定を置き換える（「」も使うなら書く）。書かなければ「」（`normal`）だけを使う。プロジェクトの外で1ファイルだけを解析するときも、この既定を使う。
- コアは表示スタイルの値を解釈しない。IRの台詞に `style` として渡し、見せ方はプレビューと出力プロファイルで決める。

### 台詞の判定

判定は2段階で行う。

1. **構文解析**：行頭から、空白（4節）と括弧（登録済みの開き括弧・閉じ括弧と、全角の（））を含まない文字が1〜20文字続き、その後に任意で（表示名）、その後に登録済みの開き括弧が来れば、**台詞候補**とする。この段階では設定DBを見ない。
2. **意味解析**：話者を、キャラクターのID、名前、呼び名の順に照合する。同じ段で2人以上のキャラクターに一致したら、解決できないものとする。
   - 解決できれば台詞にする。IRでの話者はキャラクターIDにする。
   - 解決できず、行全体が閉じ括弧で終わる場合は、W202 を出して地の文として扱う。
   - 解決できず、閉じ括弧の後に文が続く場合（`彼は「行こう」と言った。`）は、診断を出さずに地の文として扱う。
   - 未登録の話者（店員などのモブ）の台詞を書くときは、設定DBにキャラクターとして登録する。台詞の形をした地の文は、行頭の `\` で台詞の判定を止められる（4節）。

### 複数行にまたがる台詞

- 閉じ括弧が同じ行に無いときは、次の行以降を続きとして読み、閉じ括弧のある行で終える。行IDはその最後の行の末尾に付ける。
- 閉じる前に、空行、シーン見出し、ディレクティブ、選択肢の行、ジャンプの行が来るか、ファイルが終わったら、E201 を出し、その直前で台詞を終えて回復する。
- 途中のコメントの行は飛ばす（台詞の本文に含めず、打ち切りもしない）。
- 途中の `# ` で始まる行は、台詞の続きとして読む（地の文ではないので W112 は出さない）。
- 本文の中の同じ種類の括弧は、入れ子として数える。

## 7. 地の文と空行

- 地の文は、行頭の全角空白（字下げ）も含めてそのまま本文にする。
- 空行は段落の区切りにする。同じブロックの中で、前後を台詞か地の文の行に挟まれた空行だけを、IRの `break` にする。間にあるコメントは飛ばして判定し、連続する空行は1つの `break` にまとめる。
- ディレクティブ、ジャンプ、選択肢の行、ブロックの前後にある空行は、見た目の整形として捨てる。
- `break` をどう出力するか（小説の体裁での段落、ADVでの改ページなど）は、出力プロファイルで決める。
- 空行が閉じていない台詞を打ち切る働き（6節、E201）は、`break` になるかどうかに関わらない。

## 8. 文中の記法

台詞の本文、地の文、選択肢の表示文、`@選択` の問いかけ文で使える。

| 記法 | 書き方 | 備考 |
| --- | --- | --- |
| ルビ | `\|親文字《るび》` または `｜親文字《るび》` | 小説投稿サイトと同じ |
| 自動ルビ | `漢字《かんじ》` | 直前に続く漢字（`々〆ヵヶ` を含む）を親文字にする |
| 《 そのもの | `\|《` または `｜《` | ルビにしない |
| 傍点 | `《《強調》》` | |
| ウェイト | `{w 0.5}` | 秒 |
| 改ページ | `{p}` | |
| 文中の効果音 | `{se ドア}` | 意味名 |
| 文字速度 | `{speed 遅}` | `遅` / `普通` / `速` |
| 変数の埋め込み | `{=湊.名前}` | 中身は式（14節） |
| 波括弧そのもの | `{{` と `}}` | |

- 知らないインライン命令と、値の合わないインライン命令（`{w 長め}`、`{speed 速すぎ}`）には W405 を出し、そのまま文字として扱う。
- 閉じていない `{` は文字として扱う。

## 9. 行ID

```
灯「やっと来た。遅いよ」 ^k3f9
```

- 形は、1つ以上の半角空白に続く `^` と、`[0-9a-z]` の4〜12文字。
- 行末が「1つ以上の半角空白、`^`、1文字以上の英数字（`[0-9A-Za-z]`）」で終わる行は、その部分を行IDの候補として切り出す。候補が上の形に合わなければ（大文字を含む、短い、長い）、E304 を出し、候補を本文から取り除いたうえで、行IDの無い行として扱う（I302 は出さない）。
- `^` の後に英数字以外を含むもの（`^_^`）や、`^` の前に半角空白の無いものは、行IDとみなさず、本文の一部にする。
- 行IDを持てるのは、台詞（複数行なら最後の行）、地の文、`@選択` の行、選択肢の行だけ。それ以外の行に付いていれば W303 を出して無視する。
- プロジェクト全体で一意にする。重複したら、後から現れたほうに E301 を出す。
- 行IDを持てる行（台詞、地の文、`@選択` の行、選択肢の行）に行IDが無ければ、I302 を出す。**パーサは行IDを付けない**。付与はフェーズ1の整形コマンド（`scn fmt`）とエディタが行う。
- 付与のきまり（フェーズ1で実装）：
  - 新しいIDは6文字の乱数で作り、既存のIDと重ならないことを確かめる。
  - 内容を編集しても、IDは変えない。
  - 行を分割したら前半が元のIDを引き継ぎ、後半に新しいIDを付ける。
  - 行を結合したら先頭の行のIDを残す。
  - 削除した行のIDは使い回さない（乱数の長さで、事実上起きないようにする）。

## 10. ディレクティブ

- 形は `@名前 引数1 引数2 …`。引数は半角または全角の空白で区切る。空白を含む引数は `"…"` で囲む。
- ただし `@選択`（問いかけ文）、`@設定`（代入）、`@if` と `@elif`（式）は、命令名の後ろの行の残り全体を1つの引数として読む。問いかけ文には `{w 0.5}` のような空白を含む記法を書ける。
- 日本語名と英語名は同じ命令の別名で、どちらで書いてもよい。制御の命令（`@if`、`@elif`、`@else`、`@raw`、`@end`）には日本語名を設けない。
- 命令名は下の表のとおりに書き、大文字と小文字を区別する（`@BGM` と `@bgm` は使えるが、`@Bgm` は W401）。
- ブロック（`@選択`、`@if`、`@raw`）は `@end` で閉じる。閉じていなければ E103 を出し、次のシーン見出し、またはファイルの終わりで閉じたものとみなす（`@raw` の中では、行頭に空白の無い `## ` の行だけをシーン見出しとみなす。15節）。

| 日本語名 | 英語名 | 引数 | IR |
| --- | --- | --- | --- |
| `@背景` | `@bg` | 背景名 [トランジション] | `bg` |
| `@立ち絵` | `@show` | キャラ 差分 [位置] [トランジション] | `show` |
| `@退場` | `@hide` | キャラ [トランジション] | `hide` |
| `@BGM` | `@bgm` | 曲名、または `停止` | `bgm` / `bgm_stop` |
| `@SE` | `@se` | 効果音名 | `se` |
| `@効果` | `@fx` | 効果名 [秒] | `fx` |
| `@待機` | `@wait` | 秒 | `wait` |
| `@設定` | `@set` | 変数 演算子 式（14節） | `set` |
| `@選択` | `@choice` | [問いかけ文]（ブロック、11節） | `choice` |
| `@if` | `@if` | 式（ブロック、12節） | `if` |
| `@elif` | `@elif` | 式 | |
| `@else` | `@else` | なし | |
| `@呼出` | `@call` | シーンID | `call` |
| `@戻る` | `@return` | なし | `return` |
| `@エンディング` | `@ending` | エンディングID | `ending` |
| `@raw` | `@raw` | エンジン名（ブロック、15節） | `raw` |
| `@end` | `@end` | なし（ブロックを閉じる） | |

- 引数のキーワードにも日英の別名がある。位置は `左` / `中` / `右`（`left` / `center` / `right`）、`@BGM` の停止は `停止`（`stop`）。命令名の言語と関係なく、どちらで書いてもよい。IRでは英語の値にそろえる。
- `@エンディング` のエンディングIDは、シーンIDと同じ文字（5節）で書く。形が合わなければ E111。
- `@立ち絵` の引数が3つのとき、3つ目が位置のキーワードでなければ、位置を省いたものとしてトランジションとして読む。引数が4つのときは、3つ目が位置のキーワードでなければ E402。
- 秒（`@効果` と `@待機`）は半角の数（`1`、`0.5`）で書く。数でなければ E402。
- 知らないディレクティブには W401 を出す（フェーズ1でマクロとして解決する可能性があるため、エラーにしない）。
- 引数の数が合わなければ E402。`"…"` の `"` が閉じていなければ、E402 を出してその行を無視する（`@raw` は、E402 を出したうえでブロックとして開く）。
- 素材カタログ（`assets/catalog.yaml`）と照合するのは、`@背景` の背景名、`@立ち絵` の差分（キャラクターごと）、`@BGM` の曲名、`@SE` と文中の `{se}` の効果音名だけ。カタログに無ければ I403 を出し、仮素材として扱う。トランジション（`フェード` など）と `@効果` の効果名は、カタログではなく出力プロファイルで解決するので照合しない。
- `@立ち絵` と `@退場` のキャラが解決できなければ W404。そのときは差分を照合しない（I403 を重ねない）。

## 11. 選択肢

```
@選択 どう答える ^k3fc
- 「ごめん、遅くなって」 ^k3fd
  @設定 灯.好感度 += 1
- 黙ってうなずく if 勇気 >= 2 ^k3fe
  灯「……そういうところ、ずるいよね」 ^k3ff
  -> s014
@end
```

- 選択ブロックは `@選択` で始まり `@end` で終わる。閉じていなければ E103。選択肢が1つも無ければ E106。
- `@選択` の行と最初の選択肢の行の間に置けるのは、空行とコメントだけ。ほかの行（`@end` を除く）には E402 を出して読み飛ばす。選択肢の無いまま `@end` が来たときは、E106 だけを出す。
- 選択肢の行は `- 表示文 [if 式] [-> シーンID] [^行ID]`。条件は括弧で囲まない。行の右から順に、行ID、最後の ` -> `、最後の ` if ` を切り出す。` if ` と ` -> ` の前の半角空白は、`-` の後の半角空白と兼ねてよい。表示文が空なら E402（`-` だけの行、`- -> s014`、`- if 勇気 >= 2`）。
- 表示文に半角の ` if ` や ` -> ` を含めると、最後のものが条件やジャンプとして切り出される（`- What if I said no` は、`I said no` を式として読んで E601 になる）。
- 選択肢の中身は、次の選択肢の行か `@end` までの行。中身にはどの種類の行も置ける。
- 選択肢の行に `-> シーンID` を書いたときは、中身を実行してから飛ぶ（中身の最後にジャンプを書いたのと同じ）。
- 中身にジャンプが無ければ、`@end` の次の行へ進む。
- 選択ブロックの中に選択ブロックを入れてよい。内側のブロックは、外側の次の選択肢より前に `@end` で閉じる。

## 12. 条件分岐

```
@if 灯.好感度 >= 3
  灯「やっぱり、君には言っておく」 ^k3fg
  -> s013a
@elif 勇気 >= 2
  -> s014
@else
  -> s013b
@end
```

- `@if`、`@elif`（任意、複数可）、`@else`（任意、1つ）、`@end` で1つのブロックにする。
- 対応の取れない `@elif`、`@else`、`@end` には E104。2つ目の `@else` と、`@else` の後の `@elif` も E104。

## 13. ジャンプ・呼び出し・シーンの終わり

- `-> シーンID` で、そのシーンへ移る。シーンIDはプロジェクト全体で一意なので、別ファイルのシーンへもそのまま飛べる。存在しないシーンなら E501。
- ジャンプ、`@エンディング`、`@戻る` の後ろで、同じ枝の中にある行は実行されないので W502 を出す。枝は、シーンの本文、選択肢の中身、`@if`・`@elif`・`@else` のそれぞれの中身を指す。枝を区切る行（`@end`、`@elif`、`@else`、次の選択肢の行）と、空行、コメントには W502 を出さない。
- `@呼出 シーンID` はそのシーンを実行し、`@戻る` で呼び出しの次の行へ戻る。
- **シーンの終わりでは、暗黙に次のシーンへ進まない**。一本道の章でも、次のシーンへ進むには `-> シーンID` を書く。「次のシーン」を表す省略記法は設けない。
- ジャンプ、`@エンディング`、`@戻る` のどれにも当たらずにシーンが終わる経路があれば、W503（行き止まり）を出す。

## 14. 式と変数

### 文法

```
式       := 論理和
論理和   := 論理積 ( "or" 論理積 )*
論理積   := 否定 ( "and" 否定 )*
否定     := "not" 否定 | 比較
比較     := 加減 ( ( "==" | "!=" | "<" | "<=" | ">" | ">=" ) 加減 )?
加減     := 乗除 ( ( "+" | "-" ) 乗除 )*
乗除     := 単項 ( ( "*" | "/" ) 単項 )*
単項     := "-" 単項 | 基本
基本     := 整数 | 文字列 | "true" | "false" | 変数名 | "(" 式 ")"
変数名   := 名前 ( "." 名前 )?
名前     := ( 文字 | "_" ) ( 文字 | 数字 | "_" )*   // Unicodeの文字を含む。日本語の名前を使える
整数     := 半角の数字+
文字列   := '"' ( '\"' | '"'以外の文字 )* '"'
代入     := 変数名 ( "=" | "+=" | "-=" ) 式  // @設定 で使う
```

- 演算子と記号は半角で書く。`≥` などの記号は画面表示だけで使う。
- 式の中の空白（半角空白、タブ、全角空白）は、字句の区切りとして読む。
- 名前は数字で始められない（`1日目` は E601）。`and`、`or`、`not`、`true`、`false` は名前に使えない。
- 整数の割り算は切り捨てにする。

### 名前空間

- `.` の無い名前は `flag.` を補う（`勇気` は `flag.勇気`）。
- 名前空間がキャラクターのID・名前・呼び名に一致すれば、キャラクターIDにそろえる（`灯.好感度` も `あかり.好感度` も `akari.好感度`）。照合の順と、2人以上に一致したときの扱いは、台詞の話者と同じ（6節）。
- それ以外の名前空間（`周回` など）は書いたとおりに使う。

### 型と検査

- 型は真偽（`bool`）、整数（`int`）、文字列（`string`）、列挙（`enum`）。変数は `variables.yaml` で宣言する（`docs/design.md` の「変数と検証」）。
- 列挙の値は文字列で書く（`flag.ルート == "灯"`、`@設定 flag.ルート = "灯"`）。宣言の `values` に無い値は E603。
- 式の構文が崩れていれば E601、宣言されていない変数は W602、型が合わなければ E603、`+=` と `-=` を整数以外に使えば E604。
- 宣言されていない変数（W602）には型の検査をしない（E603・E604 を重ねない）。E604 を出したときは、E603 を重ねない。

## 15. 生コード

```
@raw renpy
  $ renpy.music.set_volume(0.6, channel="music")
@end
```

- `@raw` から `@end` までの行は解析せず、IRに渡す。中の行には4節の処理（行末の空白の除去、行IDの切り出し、行頭の空白の読み飛ばし、分類）を行わない。`## ` で始まる行や、` ^xxxx` で終わる行も、そのまま中身になる。
- 探すのは、前後の空白を除くと `@end` だけになる行（ブロックの終わり）だけ。
- それより前に、行頭に空白の無い `## ` で始まる行が来たら、`@end` を忘れたものとみなす。E103 を出してその行の手前で閉じ、その行はシーン見出しとして読む。`## ` で始まる行を中身に書くときは、字下げする。
- `@end` も、行頭に空白の無い `## ` の行も無いままファイルが終われば、E103 を出してファイルの終わりで閉じる。
- ブロック内の空でない行に共通する行頭の空白（半角空白とタブの並びとして、文字どおり共通な部分）だけを取り除き、それより深い字下げは保つ。半角空白とタブだけの行は空行とみなし、共通の字下げの計算から外して、空行として渡す。上の例では、IRに渡る行は `$ renpy.music.set_volume(0.6, channel="music")` になる。
- 字下げの深さを変えても（選択肢の中に移すなど）、IRに渡る行は変わらない。
- 指定したエンジンへの出力でだけ書き出し、それ以外の出力では読み飛ばす。
