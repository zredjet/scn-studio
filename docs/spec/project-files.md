# 作品フォルダの規約

状態：v0（2026-10-08、T1-5で `.scn` 以外のファイルの規約をまとめた。D044）。`.scn` の書き方は `docs/spec/scn-format-v0.md` にある。

1つの作品は1つのフォルダ（作品フォルダ）にまとめ、ツールが作るキャッシュ（`.cache/`）のほかは、すべてテキストとしてGitで管理する。ツールは、ここに書いたファイルだけを読む。決まっていないキーや項目は読み飛ばし、診断も出さない（将来のフェーズで使うものがあるため）。

## 1. フォルダの構成

```
作品フォルダ/
├─ project.toml       形式のバージョン、開始シーン、台詞の括弧、メッセージウィンドウ（必須）
├─ CLAUDE.md          AIエージェント向けの指示書（`scn new` が作る）
├─ FORMAT.md          形式の仕様と、この規約（`scn new` と `scn format-doc` が書く）
├─ concept.md         企画書
├─ style.md           文体の方針と文体見本
├─ variables.yaml     変数の宣言
├─ story/             本文（`*.scn`。下のフォルダも読む。`.` で始まるフォルダとファイルは読まない。パスの順に並べる。読めない下のフォルダは E801 で知らせる）
├─ bible/
│  ├─ types/          設定DBの型（`<型ID>.yaml`）
│  └─ entries/        設定DBのエントリ（`<型ID>/<ID>.md`）
├─ assets/
│  ├─ catalog.yaml    素材カタログ
│  └─ files/          素材のファイル
├─ ideas/             アイデアメモ（1枚1ファイル）
├─ ai/                AIタスクの定義、出自の記録、変更の提案
├─ export/            書き出したもの（台本 `script.csv`・`script.xlsx`、発注リスト `orders.csv`、プレーンテキスト `text/`、Ren'Py の `renpy/`）、収録の基準（`script-baseline.json`）と、出力プロファイル（`renpy.yaml`。11節）
├─ layout.json        フロー図のノードの位置（T1-9）
└─ .cache/            ツールのキャッシュ（Gitに入れない）
```

- `project.toml` の無いフォルダは、作品フォルダとして読まない。ほかのファイルは無くてもよく、無ければ空として扱う。
- 設定ファイルが読めない、または形が合わないときは、解析を止めずに診断にする（E801〜W807。`scn-format-v0.md` の16節）。
- 文字コードはどれもUTF-8。設定ファイル（YAML と TOML、フロントマター）の先頭の BOM（`EF BB BF`。Windows のエディタが付けることがある）は読み飛ばし、アプリで書き換えるときは残す（T2-10、D061）。

## 2. `project.toml`

```toml
format_version = 0           # 必須。今は0
title = "放課後の灯"
start_scene = "s010"         # 開始シーン。無ければ最初のシーン

[dialogue.brackets]          # 台詞の括弧と表示スタイル（scn-format-v0.md の6節）
"「」" = "normal"
"『』" = "thought"

[screen]                     # プレビューの画面の大きさ。無ければ 1280×720
width = 1280
height = 720

[message_window]             # はみ出し（W203）を調べる大きさ。無ければ調べない（プレビューは 3行×24字）
lines = 3
chars_per_line = 24
```

| キー | 型 | 内容 |
| --- | --- | --- |
| `format_version` | 整数 | 形式のバージョン。対応していなければ E803 |
| `title` | 文字列 | 作品名（`scn new` が書く。アプリの表示に使う。文字列でなければ E802） |
| `start_scene` | 文字列 | 開始シーンのID。存在しないシーンなら、検証で E501 |
| `[dialogue.brackets]` | 表 | キーは開き括弧と閉じ括弧の2文字、値は表示スタイルの名前（英字） |
| `[message_window]` | 表 | `lines`（行数）と `chars_per_line`（1行の字数、全角で数える）。どちらも正の整数。プレビューのメッセージウィンドウの大きさにも使う |
| `[screen]` | 表 | プレビューの画面の大きさ（T1-11、D050）。`width` と `height`（どちらも正の整数）。無ければ 1280×720。正の整数でなければ E802 を出して 1280×720 で見せる（本文の読み方には関わらない） |
| `[editor]` | 表 | アプリのエディタの入力補助（D047）。`normalize_ellipsis`（真偽。確定した文字の `...`・`・・・`・単独の `…` を `……` に、`--`・`－－` を `――` にする）と `indent_narration`（真偽。Enter で地の文の行を離れるとき、段落頭に全角空白が無ければ足す）。キーが無ければ切。真偽でなければ E802 を出して切として扱う。`scn new` のひな形は、どちらも `true` で書く |
| `[ai.<名前>]` | 表 | AIの接続先（T3-5、D066）。下の「AIの接続先」 |

### AIの接続先（`[ai.<名前>]`。T3-5、D066）

```toml
[ai.local]                          # 既定の接続先
provider = "openai-compatible"      # 書かなければ openai-compatible
base_url = "http://localhost:11434/v1"
model = "qwen3:8b"

[ai.cloud]
provider = "anthropic"              # base_url を書かなければ https://api.anthropic.com/v1
model = "claude-sonnet-5-5"
```

- 名前は AIタスクの `model`（`model: local`・`model: cloud`）が指す。チームで共有してよいもの（種類、URL、モデル、文脈の長さ）だけを書く。キーは書かない。
- `context_tokens`（正の整数。T3-6、D067）：モデルの文脈の長さ（トークン数）。AIタスクの文脈は、ここから返す分を除いた長さに収める（9節）。無ければ OpenAI 互換は 8192（ローカルの LLM の短い文脈でも動くように）、`anthropic` は 200000。
- `provider`：`openai-compatible`（OpenAI 互換のチャットの補完 `<base_url>/chat/completions`。Ollama、LM Studio、llama.cpp のサーバー、互換のクラウド）か `anthropic`（Messages API `<base_url>/messages`）。`base_url` は `/v1` までを書く。読んだ URL の書き方にそろえて使う（`HTTP://Host/v1/` は `http://host/v1`。末尾の `/` は除く）。
- 誤りの扱い：`ai` が表でない、`[ai.<名前>]` が表でない、`provider`・`base_url`・`model` が文字列でない、`context_tokens` が正の整数でない、は E802 を出してその接続先を読み飛ばす（本文の読み方には関わらない）。ほかのキーは読まない。知らない `provider`、`base_url` の無い OpenAI 互換、http・https でない URL、`model` が無い・空、は読み込みでは知らせず、使うとき（環境設定の画面、呼び出し）に知らせる（AI を使わない人に警告を出さない）。
- 既定の接続先：`[ai.local]` があればそれ、無ければ最初のローカルの接続先、無ければ最初の接続先（名前の順）。タイトルバーに出す。
- ローカルとクラウド：`anthropic` はいつもクラウド。OpenAI 互換は、`base_url` のホストが `localhost`・`*.localhost`・`*.local`・ループバック・プライベート（`10/8`・`172.16/12`・`192.168/16`・`fc00::/7`）・リンクローカルならローカル（この端末と LAN の中）、それ以外はクラウド。
- 端末側の設定（アプリの設定のフォルダの `ai.toml`。作品フォルダには置かない。アプリの環境設定の画面が書く）：
  - `[connections.<名前>]` の `base_url`・`model`：この端末での上書き（接続先の名前ごと。すべての作品フォルダに効く）。
  - `[cloud]` の `allowed`：この端末から送ってよいクラウドの行き先（`<provider> <base_url>`）。クラウドの接続先は、ここに無ければ送らない（設計検討書「接続」：クラウドへの送信は接続先ごとに明示的に有効にする）。
  - 読めなければ既定（上書きなし、どこも許可しない）で読み、知らせる。読めないファイルは書き換えない（画面は、直すか消すよう知らせる）。
- キー：OS のキーチェーン（macOS のキーチェーン、Windows の資格情報マネージャー）に、サービス `scn-studio`、アカウントを行き先（`<provider> <base_url>`）にして置く。作品フォルダにも端末の設定にも書かず、フロントにも渡さない（画面はキーがあるかどうかだけを知る）。`anthropic` はキーが要り、OpenAI 互換はキーがあれば `Authorization: Bearer` で送る（クラウドの多くは要るが、無くても試せる）。暗号化しない `http://` のクラウドへはキーを送らない（手元の http のプロキシ（LiteLLM など）は `openai-compatible` のローカルの接続先として使う）。
- 呼び出し：どちらもストリーミング（SSE）で頼み、サーバーがストリーミングで返さなければまとめての応答として読む。タイムアウトは、つなぐまで10秒、次のデータが届くまで180秒（全体の時間は区切らない）。取り消しはデータの合間で止める。別の URL へ移るよう返されても（3xx）ついて行かず、誤りとして知らせる（許可していない行き先や http へ、キーと本文を送らないため）。トークン数は応答の `usage`（OpenAI 互換は `stream_options.include_usage` で頼む）。無ければ文字数から見積もる（英数字4字で1、ほかは1字で1）。ローカルの行き先へは OS のプロキシを通さない。

## 3. `variables.yaml`

```yaml
flag.勇気:
  type: int
  default: 0
  scope: save
  desc: 主人公が踏み込む勇気。屋上での選択肢の条件に使う
flag.ルート:
  type: enum
  values: [共通, 灯, 紬]
  default: 共通
```

- キーは変数名で、`名前空間.名前` か `名前`（名前空間を省くと `flag.`）。キャラクターの変数は、名前空間をキャラクターIDにする（本文では名前や呼び名でも書ける）。
- `type`（必須）：`bool`・`int`・`string`・`enum`。`enum` には `values`（文字列のリスト）が要る。
- `default`：既定値。`scope`：`save`（セーブデータごと）か `persistent`（周回など、ゲーム全体）。`persistent` の変数は、本文で書かなくても警告しない（W606 を出さない）。
- `range`（整数の範囲 `[最小, 最大]`）、`desc`（用途の説明。検証の表示とAIの文脈に使う）。
- 値の検査（T2-10、D061）：`default` が型に合わない（`bool` は真偽、`int` は整数、`enum` は `values` のどれか。`string` は文字列・数・真偽のどれでもよい）、`range` が `[最小, 最大]` の整数でない・最小が最大より大きい・`int` でない変数にある、`default` が `range` の外、`scope` が `save`・`persistent` のどちらでもない、のどれかなら W807（警告）を出す。宣言は読み飛ばさない。
- プレビューの初期値（T1-11、D050）：`default` を型どおりに読む（`int` は整数、`bool` は `true`・`false`、`enum` は `values` のどれか）。無いか型に合わなければ、型の既定（`0`・`false`・空の文字列・列挙の最初の値）。`range` の外の値になっても切り詰めず、プレビューで知らせるだけ。
- アプリでの書き換え（T2-10、D061）：変数の画面で変数を選ぶと、宣言のフォーム（型、値、既定値、範囲の最小と最大、スコープ、説明）が出る。項目を直すと、その宣言の中のその項目の行だけを差し替える（行末のコメントは残す）。無い項目は宣言の最後の行の後ろに足し、空にした `default`・`scope`・`desc` は行を消す。値の書き方は5節の「アプリでの書き換え」と同じ（リストは `[a, b]`）。書いた後に読み直して、ほかの宣言と項目が変わっていないことを確かめ、変わっていれば書かずにテキストで直すよう知らせる（1行の `{ … }` で書いた宣言、値が次の行に続く項目など）。読み込みで読み飛ばされる宣言（型が無い・読めない、値の無い列挙）になる書き換えは断る（型は消せない。値の無い変数を列挙にするときは、画面が先に値を入れさせ、値・型の順に書く）。範囲は、最小と最大の両方がそろってから書く（範囲の無い変数では、先に入れた片方を覚えておく）。画面が読んだ後に外でファイルが変わっていても、その宣言のその項目が変わっていなければ今の中身に重ね、変わっていれば書かずに知らせる。
- 「＋ 変数」と、宣言の無い変数（W602）の「宣言する」は、ファイルの最後に空行を挟んで `名前:` と `type:`（列挙なら `values:` も）を足す。名前空間を省いた名前は `flag.` を付けて書く。もう宣言のある名前は断る。

## 4. `assets/catalog.yaml`（素材カタログ）

```yaml
backgrounds:
  屋上/夕方: { file: files/bg/rooftop_evening.png }
  屋上/夜:   {}                      # 未作成（仮素材）
characters:
  akari:
    dir: files/chara/akari/
    expressions:
      笑顔: smile.png
      照れ: {}
bgm:
  切ない: { file: files/bgm/setsunai.ogg, loop: true }
se:
  ドア: {}
```

- 節は `backgrounds`（背景）・`characters`（キャラクターIDごとの立ち絵の差分）・`bgm`・`se`。キーが意味名で、本文の `@背景`・`@立ち絵`・`@BGM`・`@SE`・`{se}` と照らす（カタログに無ければ I403）。
- 値が空（`{}`）の意味名は、まだファイルの無い仮素材。
- `file`（背景・BGM・SE）と、立ち絵の `dir` と差分のファイル名（`笑顔: smile.png` か `笑顔: { file: smile.png }`）は、`assets/` から数えたパスで書く。プレビュー（T1-11、D050）は、`assets/` の中にあるファイルだけを見せ、外を指すパス（`..`、絶対パス）と無いファイルは仮素材で見せる。`loop` は BGM の既定が `true`、SE の既定が `false`。Ren'Py への書き出し（11節）は、ファイルを書き出し先へ写す。
- 素材の状態（素材カタログの画面と発注リスト。T2-3、D054）：**ファイルあり**（`file` が `assets/` の中の実在するファイルを指す）、**仮素材**（カタログにあるが `{}`、または書いたファイルが見つからない）、**未登録**（本文で使われているがカタログに無い。I403）。
- アプリの素材カタログの画面は、カタログを次の2つの書き方でだけ書き換える。どちらも、ほかの行（コメント、桁そろえ、書き方）は変えず、書いた後に読み直して意図した変更だけが起きたことを確かめる。確かめられない書き方（1行の `{ … }` で書いた節やキャラクター、複数行の値など）は書き換えず、テキストで直すよう知らせる。
  - **意味名を足す**：`意味名: {}`（仮素材）の1行を、節（立ち絵はキャラクターの `expressions`）の最後の項目の次に足す。字下げはそろえ、改行はファイルに合わせる。節・キャラクター・`expressions` が無ければ、ファイル（または親）の終わりに作る。`backgrounds: {}` のような空の節は、`{}` を消して下に書く。そのままでは読めない名前（`1`、`true`、`#` を含むなど）は `"…"` で囲む。立ち絵の差分は、キャラクターが設定DBにあるときだけ足せる。
  - **ファイルを割り当てる**：`assets/` の中から選んだファイルを、その意味名の行の値にする。背景・BGM・SE は `{ file: … }`（`loop` などほかのキーは残す）。立ち絵の差分は、キャラクターに `dir` があれば `dir` から数えたファイル名（`dir` の外のファイルは割り当てない）、無ければ `assets/` から数えたパス。キーの書き方と行末のコメントは残す。

## 5. 設定DB（`bible/`）

### 型（`bible/types/<型ID>.yaml`）

```yaml
name: キャラクター
builtin: character
fields:
  - { key: aliases,      label: 呼び名, type: list<text> }
  - { key: first_person, label: 一人称, type: text }
  - { key: org,          label: 所属,   type: ref<organization> }
```

- ファイル名（拡張子を除く）が型ID。エントリのフォルダ名と同じにする（型の無いフォルダは W804）。
- `name`：型の名前。`builtin`：組み込みの型。書けるのは `character` だけで、その型のエントリが台詞の話者になる。無ければ型ID `character` を使う。
- `fields`：項目の定義のリスト。`key`（必須）、`label`、`type`（必須）、`options`（`select` と `multiselect` の選択肢）。
- 項目の型：`text`（短文）、`longtext`（長文）、`number`（数値）、`bool`（真偽）、`date`（日付、`YYYY-MM-DD`）、`select`（選択肢から1つ）、`multiselect`（選択肢からいくつか）、`asset`（素材の意味名）、`ref<型ID>`（エントリの参照）、`ref<scene>`（シーンの参照）、`list<型>`（どれかの型のリスト。例：`list<ref<scene>>`）。読めない型（打ち間違いなど）の項目の定義は読み飛ばす（E802）。`ref<型ID>` の型の定義が無くても読み飛ばさない（参照は参照切れ W806 になる）。

### エントリ（`bible/entries/<型ID>/<ID>.md`）

```markdown
---
id: akari
name: 灯
aliases: [あかり, 灯ちゃん]
first_person: わたし
---
明るく振る舞うが、転校の件を誰にも言えずにいる。
```

- `---` で囲んだフロントマター（YAML）に項目の値を、その後ろに自由な本文（Markdown）を書く。
- `id`：エントリのID。無ければファイル名（拡張子を除く）。`name`：名前。
- キャラクターには `name` が要る。`aliases`（呼び名のリスト）は話者の解決に使う。
- 伏線は型ID `foreshadow` で表し、`setup`（仕込みのシーンのリスト）と `payoff`（回収のシーン）を持たせる。`payoff` が無い・空・存在しないシーンなら W703。
- `variants`（任意。どの型のエントリでも）：避ける書き方（文字列か、そのリスト）。本文にあれば、検証の段階2で表記ゆれ（I205）として知らせる（T3-3、D064）。キャラクターの `first_person` は、台詞の一人称の表記ゆれ（I204）にも使う。
- 新しく作るエントリのID（アプリの「＋」と、未登録の話者の登録）は、英数字と `_` で書く（変数の名前空間や立ち絵の差分のキーにもなるため）。今あるIDはそのまま読む。

#### 値の書き方と検査（T1-10、D049）

- 値は、型に合わせて次のように書く。`text`・`longtext`・`asset`：文字列（数や真偽も文字列として読む）。`number`：数。`bool`：`true` か `false`。`date`：`YYYY-MM-DD` の文字列（日付として正しいもの）。`select`：選択肢のどれか（`options` が無ければ何でもよい）。`multiselect`：選択肢のリスト。`list<型>`：`[a, b]` のリスト（中身はそれぞれの型に合わせる）。
- 参照（`ref<型ID>`・`ref<scene>`）は、相手のエントリの `id` か、シーンIDを文字列で書く（例：`org: kitakaze_high`、`setup: [s021]`）。
- 書いていない値（キーが無い、空の値、空の文字列 `""`）は、どの型にも合うとみなす（壊れたまま書ける）。
- 型に合わない値は W805（段階0）、参照先の無い参照（その型のフォルダに同じ `id` のエントリが無い、無いシーン）は W806（段階1。シーンの一覧が要るため）。位置はエントリの項目のキー。型の定義の無いフォルダのエントリ（W804）は調べない。型の定義に無いキーは調べない（1節）。
- 伏線の `payoff` は W703 で調べるので、W805・W806 では調べない（同じ誤りを2回出さない。W703 はシーンIDのリストも受け付ける）。キャラクターの `name`・`aliases` は読み込み（E802）で調べるので、W805 では調べない。

#### アプリでの書き換え（T1-10、D049）

- 設定DBの画面のフォームで項目を直すと、そのキーの値だけをテキストで差し替える。ほかの行（コメント、キーの順、空行、引用の書き方、flow 形式）と本文は1バイトも変えない。直したキーの行の、行末のコメントも残す。
- 値の書き方：素のまま書ける文字列は素のまま、YAMLとして読み違える文字列（`yes`、`12`、`: ` や ` #` を含むものなど）はJSONの文字列（二重引用符）、改行を含む文字列は `|` のブロック、リストは flow 形式の `[a, b]`。空にした値は、文字列なら `""`、リストなら `[]`、ほかの型は値の無いキー（`key:`）にする。
- 無いキーは、閉じの `---` の直前に足す。フロントマターが無ければ先頭に作る。
- 値の途中にコメントがある（ブロックのリストの項目の行末のコメント、項目の間のコメントの行）キーは、差し替えるとコメントが消えるので書かない（値の後ろのコメントの行は残す）。
- 書き換えた後に読み直し、直したキー以外の項目と本文が変わっていないことを確かめる。違っていれば（ルートが flow 形式の対応表、ほかの項目が使うアンカー、同じキーが2つなど）書かずに、ソース表示で直すよう知らせる。
- `id` はフォームでは直さない（ファイル名や参照と食い違うため）。変えるときは、アプリの設定DBの画面の「IDを変える」（名前の変更。T2-8、D059）で、ファイル名・`id`・ほかのエントリの参照・アイデアメモの昇格先と、キャラクターなら本文でIDで書いた話者・立ち絵・変数の名前空間、`variables.yaml`・素材カタログ・Ren'Py の出力プロファイルのキー、企画書の主要キャラをまとめて変える。
- 本文（Markdown）は、閉じの `---` の後ろだけを置き換える。ソース表示ではファイル全体を書く。どちらも改行は今のファイルの改行（`\r\n` か `\n`）にそろえる。

#### 型定義の書き換え（T2-10、D061）

- 設定DBの画面の「型の項目」の「直す」で、型の項目の名前・型・選択肢を直す、並べ替える（↑↓）、消す、足す。「＋ 型」で型を作る（`bible/types/<型ID>.yaml` に `name:` と空の `fields:` を書く。型IDは英数字と `_`。もうあれば断る）。
- 項目は1行の `- { key: …, label: …, type: … }`（選択肢は `options: [a, b]`）で書かれたものだけを扱い、直した項目の行だけを書き換える（`}` の後ろの行末のコメントは残す。並べ替えは2つの行を入れ替え（読めない項目は飛ばして、隣の読める項目と入れ替える）、消すときはその行だけを消し、足すときは最後の項目の後ろに足す。`fields: []` と項目の無い型、終わりの改行の無いファイルにも足せる）。選択肢の要らない型に変えたら、選択肢は書かない。書いた後に読み直して、`fields` のほかと、ほかの項目が変わっていないことを確かめる。複数行で書いた項目、1行の `fields: [ … ]`、`key`・`label`・`type`・`options` のほかのキーを持つ項目は、書かずにソースで直すよう知らせる。
- 項目は `key` で指す（同じ `key` が2つあれば断る）。`key` は変えない（エントリが使っているため）。足す項目の `key` は英数字と `_` で、`id`・`name` と今ある `key` は使えない。名前は空でない1行、型は読める型（読めない型は断る）、`select`・`multiselect` には選択肢が要る。
- 項目を消しても、エントリに書いた値は消さない（型の定義に無いキーとして残る。1節）。
- 画面が読んだ後に外で型定義のファイルが変わっていれば、書かずに知らせる。

## 6. 企画書（`concept.md`）

```markdown
---
logline: 転校を言い出せない少女と、屋上でだけ本音を話す主人公の、夏休みまでの三週間
theme: 言わないことは優しさか
tone: 静か、夕方の光、切なさ多め
volume: { chars: 300000, routes: 2 }
main_characters: [akari, tsumugi, minato]
endings:
  - { id: akari_end, name: 灯エンド, intent: 秘密を受け入れて見送る }
  - { id: true_end,  name: トゥルー, intent: 両ルートの後、灯が残る理由を見つける }
---
# 企画書

やりたいこと、やらないこと、参考にしたい感触を書く。
```

- 作品に1つだけ置く。プロット系のAIタスクすべての、いちばん上の文脈になる。
- フロントマターの項目：`logline`（作品を一文で）、`theme`、`tone`、`volume`（`chars` 字数、`routes` ルート数の目安）、`main_characters`（キャラクターIDのリスト。欲求と葛藤はキャラクターのエントリに書き、ここには書かない）、`endings`（エンディングのリスト）。
- `endings` の要素は `id`（必須。本文の `@エンディング` のIDと同じ形）、`name`、`intent`（どう終わらせたいか）。検証で本文の `@エンディング` と照らす（W701・W702）。`endings` を書かなければ照らさない。
- 本文は自由。見出しは「やりたいこと」「やらないこと」「参考にしたい感触」を勧める。
- アプリの企画の画面（T2-6、D057）は、`logline`・`theme`・`tone`・`volume`（`{ chars: …, routes: … }` の形で書く）・`main_characters`・本文をフォームで直す（直したキーの行だけを差し替える）。`endings` は複数行の書き方を崩さないように、ソースで直す。企画書が無ければ、`scn new` と同じひな形で作れる。

## 7. 文体（`style.md`）

- 文体の方針と、自分で書いた文体見本を置く。AIに本文を書かせるときは、必ず文脈に入れる。
- 形は自由なMarkdown（フロントマターは読まない）。見出しは「方針」「表記」「文体見本」を勧める。表記の決まり（三点リーダ、ダッシュ、数字、一人称など）は、後の表記ゆれの検証（段階2）の手がかりにする。

## 8. アイデアメモ（`ideas/`）

```markdown
---
status: 採用
tags: [灯, 屋上]
promoted_to: scene/s012
---
放課後の屋上で、灯が転校を打ち明けかける。
```

- 1枚を1つの `.md` ファイルにする。ファイル名は自由。
- フロントマター：`status`（`未整理`・`採用`・`保留`・`没`）、`tags`（文字列のリスト）、`promoted_to`（昇格先。`scene/<シーンID>` か `<型ID>/<エントリのID>`）。
- 没にしたメモも消さない（AIの発散の材料にする）。Obsidianなどの外部エディタで書いてよい。
- 読み方（T2-6、D057）：`ideas/` の直下の `.md` だけを、ファイル名の順に読む（隠しファイルと下のフォルダは読まない）。`status` が無ければ未整理。知らない値も未整理として扱い、アプリが知らせる。`tags` に1つの文字列を書けば、タグ1つとして読む。
- 昇格（アプリの企画の画面）：
  - 設定：選んだ型のエントリ（`bible/entries/<型>/<ID>.md`）を、`id`・`name` と、メモの本文をエントリの本文にして作る。
  - スタブシーン：選んだ章（`story/` の下の `*.scn`）の末尾に、空行を挟んで `## 題名 #シーンID` と、メタ情報の `summary` だけを足す。要約はメモの本文の最初の空でない行（前後の半角空白とタブを除く）で、メタ情報のリストと読み違える `[…]` の行と `---` の行なら書かない。章の前の中身は1バイトも変えない。保存していない変更のある章、まだ取り込んでいない外部の変更のある章には足さない。
  - 伏線：型 `foreshadow` のエントリを作る（設定と同じ）。型の定義（`bible/types/foreshadow.yaml`）が無ければ、5節の標準の定義（`setup`・`payoff`）で作る。ファイルはあるのに読めない（YAML の誤りなど）ときは、上書きせずに昇格しない。
  - メモには `status: 採用` と `promoted_to` を書く（直したキーの行だけを差し替え、無ければ閉じの `---` の前に足す）。昇格先を作れないとき（使われているID、メモが外で変わっていた、メモが読み取り専用）は、何も作らず、メモも変えない。昇格先を作った後でメモを書けなかったときは、作ったものを残し、アプリが知らせる。
- アプリで足したメモは `ideas/idea-NNN.md`（使われていない最初の番号）に、`status: 未整理` と、絞り込み中のタグと、本文を書く。

## 9. AI（`ai/`）

- `ai/*.yaml`：AIタスクの定義（`docs/design.md` の「AIタスクのテンプレート化」。T3-6、D067）。下の「AIタスクの定義」。
- `ai/provenance.jsonl`：AIが書いた行の出自の記録。1行に1つのJSON。

  ```json
  {"line":"k3fa","origin":"ai","task":"external:claude-code","model":"[モデル名]","at":"2026-10-06T21:10:00+09:00"}
  ```

  | キー | 内容 |
  | --- | --- |
  | `line` | 行ID（`^` を除く） |
  | `origin` | `ai`（AIが書いた）・`ai-edited`（AIが書いたものを人が直した）・`human`（人） |
  | `task` | AIタスクの定義から実行したときはその名前（`ai/<名前>.yaml`）。外部のAIエージェントが書いたときは `external:<エージェント名>`（例：`external:claude-code`） |
  | `model` | モデルの名前 |
  | `at` | 日時（ISO 8601、時差つき） |

  - 記録の読み方（T3-4、D065）：1行に1つの記録。同じ行IDの記録が2つ以上あれば、いちばん後ろのものが今の出自。読めない行（JSON でない、`line`・`origin` が無い）は読み飛ばして知らせる。記録の無い行は人が書いた行とみなす（`human` の記録は書かなくてよい）。行の単位で記録する（シーンや文字の単位にはしない）。
  - 書き足し方：今の中身の後ろに行を足すだけで、ほかの行は1バイトも変えない（終わりに改行が無ければ足し、改行は今のファイルにそろえる。`ai/` が無ければ作る）。記録は消さない（行を消しても、記録は残る。一覧には本文にある行だけを出す）。
  - 外部のAIエージェントは、`scn fmt --provenance <タスク> --model <モデル名>` で、付けた行IDを `origin: ai` として書き足す（時刻は協定世界時の `Z`）。書き始める前に `scn fmt`（`--provenance` なし）で人の行に行IDを付けておけば、記録されるのは自分が書いた行だけになる（D041）。
  - アプリで、今の出自が `ai` の行を直して保存すると、`origin: ai-edited`（タスクとモデルは前の記録から）を書き足す。名前の変更（F2）で保存していない変更ごと書くときも同じ（名前の置き換えそのものは数えない）。直したかは、人が直し始めた元の本文（開いた・保存した・読み込み直したときの中身）と書く本文を、行IDごとの範囲（台詞・地の文・`@選択` の行・選択肢の行）の文字で比べて決める。行ごとに行頭と行末の半角空白・タブ（字下げ）と行IDは比べない。外部のエディタの変更は、誰が直したか分からないので数えない（外の変更とぶつかって自分の変更を残したときは、外の中身と同じになった行を数えない。アプリが覚えていた競合の元があれば、それを人が直し始めた元にする）。もう `ai-edited` の行と、人の行には書き足さない。
  - 行を分けたとき：新しい行IDが付いた部分には記録を引き継がない（人の行とみなす。分けた残りの行は文字が変わるので `ai-edited` になる）。行をつないだとき：つないで無くなった AI の行（`ai`・`ai-edited`）のすぐ前の行が残り、文字が変わって、無くなった行の文字を含んでいれば、残った行を `ai-edited` にする（人の行でも、AI の文を含むため）。
  - 外部のエージェントが書いた行に、`scn fmt --provenance` より先にアプリの保存で行IDが付くと、その行は人の行とみなされる（誰が書いたかをアプリは知らない）。作品フォルダの指示書の手順（書き終えたらすぐ `scn fmt --provenance`）で防ぐ。
  - アプリは `ai/provenance.jsonl` が外で変わったら（エージェントが書き足した、`git pull` など）、AI の行の印を取り直す。
  - `scn provenance [project-dir] [--json] [-o 書き出し先]` とアプリの「出力」の画面の「AIの出自」：本文にある行のうち、今の出自が `ai`・`ai-edited` の行の一覧（行ID、ファイル、シーン、出自、タスク、モデル、日時、本文）と数。`-o`（アプリは `export/provenance.csv`）で CSV（UTF-8 の BOM 付き、CRLF。台本と同じ形）に書く。賞や公募の申告に使う。
- `ai/proposals/`：AIエージェントが、人の書いた行への変更案を置く（日付つきのMarkdown。対象の行ID、今の文、案、理由）。下の「提案」。

### 提案（`ai/proposals/*.md` とアプリの提案。T3-8、D069）

```markdown
---
task: external:claude-code
model: [モデル名]
at: 2026-10-08T12:00:00Z
---

## ^k3fg
- 今：灯「やっぱり、君には言っておく」
- 案：灯「やっぱり、君には言っとく」
- 理由：口調メモの軽口に合わせる
```

- 1つの提案は、行ID・今の文・案・理由（任意）。今の文と案は、行の中身（行頭の半角空白・タブの字下げと行末の ` ^行ID` を除いたもの。段落頭の全角空白は中身に含む）。値の末尾にその行の ` ^行ID` が付いていれば除いて読む。`ai/proposals/` の直下の `*.md` を名前の順に読む。フロントマター（任意）の `task`・`model` は、採用した行の出自の記録に使う（無ければ `external:proposals`・`unknown`。時刻は採用した時刻）。`at` は画面に見せるだけ。見出し `## ^行ID`（`^` は省いてもよい）の下の箇条書き `- 今：`・`- 案：`・`- 理由：`（`before`・`after`・`reason`、半角の `:` でもよい）を読み、値を囲む `` ` `` は除く。案の無い提案、行IDでない見出しは読み飛ばして知らせる。
- アプリの提案のタスク（`output: diff`）の応答は、1行に1つの JSON（`{"line": "行ID", "before": "今の文", "after": "案", "reason": "理由"}`。読み方は指摘と同じく崩れていても読めた分）。アプリの中だけに持つ。
- 採用（アプリの「AI」の画面の提案。人の操作だけ）：提案を今の本文（保存していない本文も）と照らし、行ごとに文字の差分（削る文字と足す文字）を見せる。「採用」「採用できるものをすべて採用」で、採用できる行だけを、行頭の字下げ・行IDとその前後の空白を残して案に置き換え（今の行が段落頭の全角空白で始まり、案に無ければ残す）、その章を保存する（保存していない変更も一緒に保存する）。採用した行の出自を `ai`（タスクとモデル）として書き足す（人がその後に直せば `ai-edited`）。次のときは採用しない：本文にその行IDが無い・重なっている（ほかの章も数える。コメントの行と `@raw` の中は数えない）、複数行の台詞（行IDのある最後の行だけでは照らせない）、今の行が提案の「今」と違う（本文が変わった。前後の空白は比べない）、「今」が無い、案が空・改行（`\r` も）を含む・行IDを含む、行の種類が変わる（コメント・見出し・ジャンプ・命令・選択肢と、台詞・地の文の入れ替え）、当てた後の章を解析すると有効な行IDの集まりが変わる（台詞の閉じ括弧を落とす、`@選択` をほかの命令にするなど）か構文の誤り・警告が増える、もう案と同じ。外部の変更とぶつかっている章には採用しない。「却下」は画面の中だけで（画面を切り替えても残す。作品を開き直すと忘れる）、ファイルは書き換えない。提案ファイルの中身が外で変わったら、照らし直して却下を忘れる。
- `ai/proposals/` が外で変わったら、アプリは提案ファイルの一覧を読み直す。

### AIタスクの定義（`ai/*.yaml`。T3-6、D067）

```yaml
# ai/tone_check.yaml
name: 口調チェック
level: review
model: local
context: [scene, characters.speech, characters.first_person]
output: findings
prompt: |
  以下のシーンの台詞が、各キャラの口調メモと一人称に沿っているか確認し、
  外れている行を行IDつきで指摘してください。
```

- タスクの名前はファイル名から拡張子を除いたもの（`tone_check`）。出自の記録の `task` と、ほかのタスクの `checks` が指す。`ai/` の直下の `*.yaml` だけを読む（`ai/proposals/` などの下のフォルダは読まない）。

| キー | 型 | 内容 |
| --- | --- | --- |
| `name` | 文字列 | 表示の名前。無ければタスクの名前 |
| `level` | 文字列 | 関わり方の段階：`review`（指摘）・`propose`（提案）・`generate`（生成）・`auto`（自律）。無ければ `review` |
| `model` | 文字列 | 接続先の名前（`project.toml` の `[ai.<名前>]`）。無ければ既定の接続先（2節） |
| `context` | 名前のリスト | 文脈に入れる項目（下の表）。無ければ `[scene]` |
| `output` | 文字列 | 出力の形。`review` は `findings`（行IDつきの指摘。既定）か `summary`（シーンの要約。`.cache/` に入れる）、`propose` は `diff`（行IDつきの差分。既定）か `proposals`（提案ノード）、`generate`・`auto` は `draft`（本文への書き込み。既定） |
| `scope` | 文字列 | 書き込んでよい範囲（`generate`・`auto`）。今は `empty_only`（スタブと空き）だけで、既定も `empty_only` |
| `branch` | 文字列 | 大きな実行のブランチ名のひな形（`ai/{task}-{date}`） |
| `checks` | 名前のリスト | 自律で通す点検（`check` と、ほかのタスクの名前） |
| `max_iterations` | 正の整数 | 自律の反復の上限 |
| `budget` | 表 | `{ tokens: 正の整数 }`。1回の実行のトークン数の上限 |
| `prompt` | 文字列 | 依頼の文（必須） |

- 誤りの扱い：YAML として読めない、UTF-8 でないファイルは E801（そのタスクを読み飛ばす）。対応表でない定義は E802（読み飛ばす）。キーの型の誤り・知らない値は E802 を出して、そのキーを既定にする（知らない `level` は `review`、`level` に合わない `output` は段階の既定、知らない `context` の項目はその項目だけを読み飛ばす）。`prompt` が無ければ E802（タスクは一覧に出すが、実行できない）。ほかのキーは読まない。`model` の接続先が無い、`checks` の名前が無い、は使うときに知らせる（AI を使わない作品に警告を出さない）。
- 文脈の項目：

| 項目 | 入れるもの |
| --- | --- |
| `scene` | 今のシーンの本文（見出しから同じファイルの次の見出しの手前まで。行IDつきのまま）。このタスクはシーンを選んで実行する |
| `characters` | 登場キャラ（今のシーンで話者・`@立ち絵`・`@退場` に出た順。話者も `@立ち絵` も無いシーン（スタブなど）では、シーンの本文（メタ情報の summary を含む）に名前か呼び名が出るキャラクターを出た順に。シーンが無ければ全員）のエントリ：型の定義の順の項目（参照はエントリの名前にする）と本文 |
| `characters.<項目>` | 登場キャラの、書いた項目だけ（`characters.speech`、`characters.first_person` など。`characters.body` は本文）。複数書ける |
| `terms` | 言及された用語：キャラクター以外のエントリのうち、名前か呼び名（`aliases`）が今のシーンの本文（見出しからの全体。メタ情報やコメントも含む）に出るもの（シーンが無ければ全部）。項目と本文 |
| `variables` | 関係する変数の宣言（今のシーンで読み書きする変数。シーンが無ければ全部）：型、値、既定、範囲、スコープ、説明 |
| `previous_summaries` | 前のシーンまでの要約：開始シーンから今のシーンまでの、シーンの辺の上の最短の道（条件は見ない）にあるシーンの要約 |
| `concept` | 企画書（`concept.md`）の全体 |
| `style` | 文体（`style.md`）の全体（文体見本を含む）。生成と自律（`generate`・`auto`）のタスクでは、書いていなくても入れ、`style.md` が無ければ実行しない |
| `route_summaries`・`chapter_summaries`・`scene_summaries` | シーンの要約を、ルート（メタ情報の `route`）ごと・章（ファイル）ごと・全部を順に |

- 組み立て方：節は「企画書、文体、ルート・章・シーンの要約、前のシーンまでの要約、キャラクター、用語、変数、今のシーン」の順（上から下へ）に並べ、後ろに依頼（`prompt` と対象のシーン）を置く。指示（system）には、共作者としての決まり（人の行を書き換えない）、`.scn` 形式のあらまし、出力の形の指示（`output` ごと）を書く。
- 文脈の長さ：接続先の `context_tokens`（2節）から、返す分（4分の1、多くて4096）を除いたものを上限にする。トークン数は文字数から見積もる（英数字4字で1、ほかは1字で1）。上限に入らなければ、前のシーンまでの要約 → シーンの要約 → 章の要約 → ルートの要約 → 用語 → キャラクター（まず一人称と口調メモだけにし（`characters.<項目>` なら、書いた項目のうちの一人称と口調メモだけ）、次に節ごと）→ 変数 → 企画書 → 文体 の順に削る。今のシーンと依頼は削らない。生成と自律（`generate`・`auto`）では文体を削らない（設計検討書「生成の進め方」：文体見本は必ず入れる）。それでも入らなければ、実行せずに知らせる。
- シーンの要約：`.cache/summaries.json`（10節）の要約を、要約を作ったときのシーンの本文と今の本文が同じとき（ハッシュが合うとき）だけ使う。無いか本文が変わっていれば、メタ情報の `summary`、それも無ければ題名だけにする（本文が変わったシーンは、作り直すよう知らせる）。要約を作るのは `output: summary` のタスク（シーン要約）。
- 組み込みのタスク：`scn new` は次の9つの定義を置く（サンプルにもある）。中身は直してよく、足してもよい（設計検討書「AIタスクのテンプレート化」）。

| 名前 | 内容 | `level` | `output` |
| --- | --- | --- | --- |
| `setting_check` | 設定矛盾チェック | `review` | `findings` |
| `tone_check` | 口調チェック | `review` | `findings` |
| `wording_check` | 表記ゆれと誤字 | `review` | `findings` |
| `scene_summary` | シーン要約 | `review` | `summary` |
| `thin_branches` | 分岐の薄さの指摘 | `review` | `findings` |
| `rephrase` | 言い換え候補 | `propose` | `diff` |
| `draft_stub` | スタブの本文を下書き | `generate` | `draft` |
| `route_skeleton` | ルート骨格を作る | `generate` | `draft` |
| `draft_chapter` | 章を下書きまで仕上げる | `auto` | `draft` |

- 対象：今はシーンだけを選べる（`scene`・`previous_summaries` に使う）。章やルートを対象にするタスク（`draft_chapter`・`route_skeleton`）の対象の指定は、生成と自律を作るとき（T3-9）に足す。
- `scn ai context <タスク> [project-dir] [--scene ID] [--tokens N] [--json]`：組み立てた文脈（指示と依頼）を出す（LLM は呼ばない）。節と削った節は標準エラーに出す。実行できなければ終了コード1。
- 実行（T3-7、D068）：アプリの「AI」の画面で、タスクを選び（シーンを使うタスクは対象のシーンも）、「実行」で文脈を組み立てて接続先に送る。指摘の段階（`review`）と、提案の段階の `output: diff`（T3-8）を実行する（提案ノードの `proposals` は T3-10、生成と自律は T3-9）。クラウドの接続先では、送る中身（指示と依頼、見積もり、削った節）を見せてから「送る」で送る（ローカルでも「送る中身を見る」でいつでも見られる）。見せた中身の要約値（行き先・モデル・指示・依頼のハッシュ）を添えて頼み、コアは組み立て直した中身の要約値が同じときだけクラウドへ送る（見せた後に本文や設定が変わったら、送らずに確かめ直させる）。返す分の上限（`max_tokens`）は、文脈の長さから文脈の上限を除いた分。届いた文字の数を進み具合として見せ、取り消せる。
- 指摘の読み方（`output: findings`）：1行に1つの JSON（`{"line": "行ID", "severity": "error|warning|info", "message": "…"}`。行に結びつかなければ `"scene": "シーンID"`）を基本に、JSON の配列・`{"findings": [...]}`（前置きの文があっても、最初の `[`・`{` から最後の `]`・`}` までを読む）・コードブロックの囲み・箇条書きの印・末尾のカンマも読む。`line` の `^` は除く。`severity` は `error`・`warning`・`info`（`エラー`・`警告` も）で、ほかは `info`。`message`（無ければ `text`・`comment`）の無いもの、読めない行は「読めなかった行」として見せ、止めない。行IDは本文の行IDから位置を引く（無ければ「本文に無い行ID」と見せる）。行もシーンも（本文に）無い指摘は、対象のシーンに付ける。
- 指摘の持ち方：アプリの中だけに持ち、ファイルには書かない（作品を開き直すと消える）。エディタで指摘のある行に印（薄い地と点の下線。ツールチップに指摘）を付け、文脈パネルの「AIの指摘」に今のシーンの指摘を出す（行へ移動、閉じる）。行IDで結びつけるので、編集で行が動いても付いていく（「行へ移動」も、今の本文の中を行IDで探す）。同じタスクを同じ対象でやり直したら、前の指摘を置き換える。
- シーン要約（`output: summary`）：応答の文（まわりの括弧・引用符・コードブロックの囲みを除く）を、シーンの本文のハッシュと一緒に `.cache/summaries.json` に入れる。取り消した実行の結果は入れない。
- 設定DBの画面の「AIに渡す内容」：エントリが、どのタスクにどの部分（項目と字数）で渡るか。キャラクターは登場するシーンで（`characters`）、ほかのエントリは名前が出るシーンで（`terms`）。


## 10. ツールが作るファイル

- `.cache/summaries.json`：シーンの要約のキャッシュ（T3-6、D067）。シーンIDごとに、要約と、要約を作ったときのシーンの本文のハッシュ（行末の行IDを除いた本文の FNV-1a 64 ビットの16進。保存で行IDが付いただけでは変わらない）を持つ（`{"scenes": {"s010": {"hash": "…", "summary": "…"}}}`）。シーン要約のタスクが書く。消してもよい（作り直す）。`scn new` の `.gitignore` は `.cache/` を Git に入れない。読めなければ知らせて、キャッシュを使わない。

- `FORMAT.md`：`.scn` の仕様（`scn-format-v0.md` の1〜16節）と、この規約をまとめたもの。`scn new` が作り、ツールの版が上がったら `scn format-doc` で書き直す（D044）。手で直さない。
- `CLAUDE.md`：`scn new` が共通のひな形から作る。作品のきまり（視点、口調など）は、作品ごとに書き足す。
- `layout.json`：フロー図で動かしたノードの位置（T1-9、D048）。アプリが書く。形は次のとおり。粒度（`scene`・`chapter`・`route`）ごとに、ノードのID（シーンID、章のファイル、ルートの名前。ルートの無いシーンのまとまりは空文字列）と位置（整数）を持つ。キーは名前の順に書く。位置の無いノードは自動で置く。無いシーンを指す位置も残す（そのシーンが戻ってきたときに使う）。壊れていたら（JSONでない、表でない）自動の配置で表示し、ノードを動かしても上書きしない（Gitのマージの印などを消さないため）。フロー図の「自動整列」を押したときだけ書き直す（中身を読めないので、ほかの粒度の位置も空になる）。

  ```json
  {
    "chapter": {},
    "route": {},
    "scene": {
      "s010": { "x": 16, "y": 36 }
    },
    "version": 1
  }
  ```
- `export/script.csv`・`export/script.xlsx`：台本（T1-12、D051。Excel 形式は T2-10、D061）。`scn export script`（`--format xlsx` で Excel 形式）とアプリの「出力」の画面が書く（書くたびに作り直すので、手で直さない）。列は、行ID、シーン（シーンIDと題名）、キャラ（表示名があれば `名前（表示名）`）、台詞、直前の地の文、ボイスファイル名、備考。
  - 1行が1つの台詞（`@選択` の中身や `@if` の枝の台詞も、IRの順＝ファイルのパスの順と、ファイルの中の順）。地の文は行にせず、同じシーンでその台詞より前にある、いちばん近い地の文を「直前の地の文」に入れる。選択肢の中身と条件の枝では、ブロックの前の地の文を引き継ぐ。ブロックの中の地の文は、ブロックの後ろへ持ち越さない（どの枝を通ったか分からないため。ブロックの後ろの台詞は、ブロックの前の地の文を使う）。
  - 台詞は括弧を付けずに書く。ルビは `親文字（読み）`、傍点は中身、`{w}`・`{p}`・`{speed}` は書かず、文中の効果音（`{se}`）は備考に、変数の埋め込みは `{=式}` のまま、複数行の台詞の改行は欄の中の改行にする。
  - ボイスファイル名は `キャラID_行ID`（拡張子なし。エンジンごとの拡張子は出力プロファイルで決める）。行IDの無い台詞（形の合わない行ID E304 の台詞を含む）は、行IDとボイスファイル名を空にして出し、備考に「行IDなし」と書き、その数を知らせる（行は落とさない。保存か `scn fmt` で行IDを付ける）。行IDが重なっている台詞（E301）は、備考に書く（ボイスファイル名も重なる）。
  - 備考：AI下書きのシーンの台詞は「AI下書き」、表示スタイル `thought` は「心の声」（ほかの表示スタイルは名前）、表示名、文中の効果音、行IDなし、行IDの重なり。
  - CSV を Excel で開くと、数字だけの行ID（`012345`）や指数の形の行ID（`12e345`）は数として読まれ、`=`・`+`・`-`・`@` で始まる台詞は数式として読まれることがある。台本は書き換えずに書く（Excel では、取り込みで列を文字列にして開くか、Excel 形式で書き出す）。
  - CSV は RFC 4180（`"`・`,`・改行を含む欄は `"` で囲む）で、文字コードは UTF-8（BOM付き）、改行は CRLF（Excel でそのまま開けるように）。
  - Excel 形式（.xlsx）は、シート「台本」1枚に同じ列を書く。欄はすべて文字列（行IDが数や日付に、`=` で始まる台詞が数式に変わらない）、見出しの行は太字で固定し、欄の中の改行は折り返して見せる。
  - 再収録候補（T2-10、D061）：収録の基準（`export/script-baseline.json`）があれば、基準の後に話者か台詞の文字が変わった台詞の備考に「再収録候補（収録の基準の後に変わった）」、基準に無い行IDの台詞の備考に「収録の基準の後に足した」と書き足し、変わった・足した・無くなった台詞の数を知らせる。地の文と備考の違いは数えない。行IDの無い台詞と、台本の中で重なっている行ID（E301）の台詞は比べない（基準にも記録しない）。無くなった台詞は、行IDも知らせる。
- `export/script-baseline.json`：収録の基準（T2-10、D061）。台本を書き出すときに「収録の基準として記録する」（`scn export script --baseline`、アプリの「出力」の画面のチェック）と、書き出した台本で置き換える。行IDごとに、ボイスファイル名（話者と行ID）と台詞の文字のハッシュ（FNV-1a 64 ビットの16進）を持つ（`{"lines": {"k3f9": "…"}}`）。収録に出すときに記録し、次からの台本で直した台詞を見つける。チームで共有するなら Git に入れる。読めなければ知らせて、再収録候補を付けずに書き出す。
- `export/orders.csv`：発注リスト（T2-3、D054）。`scn export orders` とアプリの素材カタログの画面が書く（書くたびに作り直す）。まだファイルの無い素材（仮素材と未登録）を1行ずつ、種類（背景・立ち絵・BGM・SE）、キャラクター、意味名の順に書く。列は、種別、名前（立ち絵は `キャラの名前/差分`）、キャラ、差分、使用回数、初出（シーンID）、使用シーン（初めて使われた順、空白区切り）、備考（カタログに無い、キャラクターが設定DBに無い、書いたファイルが見つからない、本文で未使用）。本文で使われていない仮素材も書く（備考で分かる）。CSV の形は台本と同じ（UTF-8 の BOM 付き、CRLF、RFC 4180）。立ち絵は、キャラと差分の列で、表計算のピボットでキャラ×差分の表にできる。
- `export/text/<道の名前>.txt`：プレーンテキスト（T2-5、D056）。`scn export text` とアプリの「出力」の画面が書く（書くたびに作り直す）。道（共通・ルート・エンディング）を一本道にした通読用のテキスト。
  - 道：「共通のみ」は開始シーンのルートだけ（ほかのルートのシーンに入る手前まで。選択肢は選べる最初のもの）。開始シーンにルートが無い作品では「通し」（選べる最初の選択肢で終わりまで）。「〇〇ルート」は、そのルートのエンディングのうち、本文の順で着ける最初のものまでの最短経路で読む（どれにも着けなければ、そのルートの最初のシーンまでの最短経路で入り、後は選べる最初の選択肢）。「エンディング 〇〇 まで」は、そのエンディングまでの最短経路。最短経路はカーソル位置から再生（D055）と同じ。ルートはシーンのメタ情報の `route`。着けない道は書かない（知らせる。`--route`・`--ending` で1つの道を指定したときは終了コード2）。
  - 1行目は `作品名（道の名前）`。シーンの見出しは `◆ 題名`（`@呼出` で呼ばれたシーンには見出しを書かず、呼び出し元の本文に続ける）。小説の形にする：話者名は書かず、台詞は表示スタイルの括弧で囲む。地の文は書かれたとおり。段落の区切り（空行）は空行。
  - ルビは `｜親文字《読み》`（なろう・カクヨムの記法）、傍点は `《《傍点》》`（カクヨムの記法）。本文の `《` は、ルビと読まれないように `｜《` と書く。`{w}`・`{p}`・`{speed}`・文中の効果音は書かない。変数の埋め込みは、道を実行した値（決まらなければ `{=式}`）。
  - 注記（既定で書く。`--no-notes` で書かない）：選んだ選択肢を `〔選択：表示文〕`、エンディングを `〔エンディング：ID〕`。
  - 文字コードは UTF-8（BOM なし）、改行は LF。ファイル名に使えない文字（`/`・`\`・`:` など）は `_` にする。
- `export/renpy/`（出力プロファイルの `output`）：Ren'Py への書き出し（T2-2、D053）。11節。
- `.cache/`：索引などのキャッシュ。Gitに入れない（`scn new` が `.gitignore` に書く）。

## 11. 出力プロファイル（`export/renpy.yaml`）と Ren'Py への書き出し

T2-2、D053。`scn export renpy` とアプリの「出力」の画面が、IRをこのプロファイルに従って Ren'Py のスクリプトにする。書き出しは一方向で、書き出したものは手で直さない（本文を直して書き出し直す。エンジン側の調整は本文の `@raw renpy` で書く）。

```yaml
# export/renpy.yaml
target: renpy
images:
  背景:   "bg {file_stem}"
  立ち絵: "{char_id} {expr_stem}"
positions:   { 左: left, 中: center, 右: right }
transitions: { フェード: fade, 即時: None }
fx:          { 揺れ: "with vpunch" }
voice:       { pattern: "voice/{char_id}_{line_id}.ogg" }
font: SourceHanSansLite.ttf
```

### キー

ファイルが無ければ、すべて既定で書き出す。

| キー | 値 | 既定 | 意味 |
| --- | --- | --- | --- |
| `target` | `renpy` | | 対象のエンジン。ほかの値なら知らせる |
| `output` | 作品フォルダの中を指す相対パス | `export/renpy` | 書き出し先（Ren'Py のプロジェクトのフォルダ）。CLI の `-o` で上書きできる |
| `images` | `背景`（`background`）・`立ち絵`（`sprite`）の対応表 | `bg {file_stem}`・`{char_id} {expr_stem}` | 画像の名前のひな形。`{file_stem}` はカタログのファイル名（拡張子を除く）、`{char_id}` はキャラクターID、`{expr_stem}` は差分のファイル名 |
| `positions` | `左`・`中`・`右`（`left`・`center`・`right`）から Ren'Py の位置へ | 同じ名前（`left` など） | `@立ち絵` の位置 |
| `transitions` | トランジションの名前から Ren'Py のトランジションへ。`None` か `null` なら付けない | `フェード: fade`、`即時: None` | `@背景`・`@立ち絵`・`@退場` のトランジション。対応の無い名前は `dissolve` にして知らせる |
| `fx` | `@効果` の名前から Ren'Py の文へ | なし | 対応の無い効果は書き出さずに（コメントにして）知らせる。秒があれば、続けて `pause 秒` を書く |
| `voice` | `{ pattern: "…" }`（`{char_id}`・`{line_id}`。`assets/` から数えたパス） | なし | 台詞の前に `voice` を書く。ファイルが `assets/` の中にある台詞だけ |
| `ending` | Ren'Py の文 | `$ renpy.full_restart()` | `@エンディング` で書く文（タイトルへ戻る） |
| `variables` | 変数名から Ren'Py の名前へ。キーは本文と同じくそろえた名前（`akari.好感度`、名前空間を省いた変数は `flag.勇気`） | 自動 | 変数の名前を決めるとき。書いた名前はそのまま使い、自動の名前と重ならないよう取っておく |
| `characters` | キャラクターIDから Ren'Py の名前へ | 自動 | `Character` の名前を決めるとき（同上） |
| `font` | フォントのファイル（`.ttf`・`.otf`・`.ttc`。作品フォルダから数えたパスか、絶対パス） | なし | 台詞と画面の文字のフォント。Ren'Py の既定のフォントには日本語が無い |
| `start_label` | 真偽 | `true` | `label start`（開始シーンへ飛ぶ）を書くか。自分の `label start` を持つプロジェクトに書き出すときは `false` |

- 値の型が合わない、`output` が作品フォルダの外を指す、YAMLとして読めないときは、その値を読み飛ばして既定で書き出し、何を読み飛ばしたかを知らせる（`scn check` の診断にはしない。書き出しのときだけ読むため）。ほかのファイルと同じく、決まっていないキー（フェーズ3の `command` など）は黙って読み飛ばす。

### 書き出すもの

書き出し先の `game/scn/` の下だけを、書き出すたびに消して作り直す。`game/` のほかのファイル（Ren'Py のランチャーが作る `gui.rpy`・`screens.rpy`・`options.rpy`、置いたフォントなど）には触れない。`game/scn/` があって、書き出したもの（`scn_defs.rpy` の1行目の印）でなければ、消さずに止める。消すときは、印のファイルを最後に消す（途中で消せないファイルがあっても、次の書き出しで消せるように）。

| ファイル | 中身 |
| --- | --- |
| `game/scn/scn_defs.rpy` | 整数の割り算の関数（`_scn_div`）、`gui.rpy` の無いプロジェクトのための設定（画面の大きさは `[screen]`、Ren'Py の既定の画面）、フォント（読めるときだけ使う）、`Character` の定義、変数の `default`、画像の定義 |
| `game/scn/scn_start.rpy` | `label start`（`start_scene`、無ければ最初のシーンへ飛ぶ） |
| `game/scn/story_<章のファイル名>.rpy` | 章のファイルごとに、シーンのラベル |
| `game/scn/<assets/ から数えたパス>` | カタログのファイル、ボイス（`assets/` の中にあるものだけ）を写したもの |
| `game/scn/fonts/<ファイル名>` | `font` のファイルを写したもの。見つからなければ写さず、`game/` に同じ名前のファイルを置けば使う |

### 名前

- ラベルはシーンID。数字か `_` で始まるID、Ren'Py が特別に扱う名前（`start`・`main_menu` など）は `s_` を付ける。
- キャラクターと変数は、Python の名前として使える形にする。使える文字は、ASCII の英数字と `_` と、Unicode の識別子の文字（XID_Continue。日本語の文字を含む）のうち基本面（U+00A0〜U+FFFD）のもの。ほかの文字（`.`、`①`、基本面の外の文字など）は `_` にする。名前の初めに使えない文字（数字、`_` など）で始まる名前と、Python や Ren'Py の名前（`if`・`int`・`config`・`narrator` など）と重なる名前には、`c_`（キャラクター）・`v_`（変数）を付ける。重なれば後のものに `_2`、`_3` …を付ける。`scope: persistent` の変数は `persistent.` の下に置く。Python は名前を NFKC でそろえるので、全角と半角だけが違う名前（`ｈｐ` と `hp`）は同じ名前になる（見分けない）。
- 画像の名前は、ひな形を英小文字・数字・`_` の語にしたもの（数字で始まる語は `i` を付ける）。ファイルが無いか、ファイル名に英数字が無い素材（`屋上.png`）は、意味名から決まる `ph_` と16進の6桁を使う。英数字の無いキャラクターID（立ち絵のタグ）は、`c_` と16進の6桁。重なれば `_2` …を付ける。
- 画面に見せる名前（キャラクターの名前、表示名、仮素材の札）の `[`・`{`・`【` は重ねる。

### 変換

| `.scn` | Ren'Py |
| --- | --- |
| シーン | `label`。出口の無い経路が残るシーン（W503）の終わりには、`（行き止まり：…）` を見せてタイトルへ戻る文を置く（Ren'Py のラベルは次のラベルへ進むため） |
| 台詞 | `Character` の say 文。括弧は表示スタイルの括弧を `what_prefix`・`what_suffix` で付ける。表示名や表示スタイルの違う台詞は、`kind` で元のキャラクターを引き継ぐ `Character` を別に作る（空の表示名は名前なし） |
| 地の文 | 名前の無い say 文 |
| `{p}` | 次の say 文。括弧は最初の文の初めと、最後の文の終わりにだけ付ける（say 文の引数 `what_prefix`・`what_suffix` で外す） |
| `{se 名前}` | `{nw}` で止めずに効果音を鳴らし、`extend` で続ける（`extend` は元の say 文の引数を引き継ぐので、括弧を両方とも書く）。`{se}` の直後の `{p}` は、クリックを待ってから次の say 文にする。選択肢と問いかけ文の中の `{se}` は書き出さずに知らせる |
| ボイス | ボイスのある台詞を `{p}`・`{se}` で分けたときは、続きの文の前に `voice sustain` を書く |
| `{w 秒}`・`{speed 遅}`・`{speed 速}` | `{w=秒}`・`{cps=*0.5}`・`{cps=*2}` |
| ルビ・傍点 | `{rb}親文字{/rb}{rt}読み{/rt}`。傍点は1文字ずつ `﹅` のルビ |
| `{=式}` | `[名前!q]`（`!q`：値の中の `{` をタグとして読まない）。変数でない式は、一時変数に入れてから埋め込む。真偽の値（真偽の変数、比較、`and`・`or`・`not`）はプレビューと同じく `true`・`false` と見せる。構文の崩れた式（E601）は書かれたとおりに見せる |
| 本文の文字 | Ren'Py が特別に読む `[`・`{`・`%`・`【` は重ねる |
| `@背景`・`@立ち絵`・`@退場` | `scene`・`show … at 位置`・`hide`（トランジションは `with`） |
| `@BGM`・`@BGM 停止`・`@SE` | `play music`（カタログの `loop: false` なら `noloop`）・`stop music`・`play sound`。ファイルの無い音は鳴らさない（コメントを書く。`@BGM` は前の曲を止める） |
| `@効果`・`@待機` | プロファイルの `fx` の文・`pause 秒` |
| `@選択` | `menu`。問いかけ文は最初の行、条件は `if`（構文の崩れた条件は `if False`）。中身の無い選択肢は `pass`。選択肢がすべて条件付きなら、どれも選べないとき（Ren'Py の `menu` は次の文へ進んでしまう）は、`menu` の前で行き止まりとして止まる。選択肢の無い `@選択`（E106）は、`menu` を書かずに行き止まりにする |
| `@if`・`@elif`・`@else` | `if`・`elif`・`else`（構文の崩れた条件は `False`） |
| `@設定` | `$ 変数 演算子 式`。整数の割り算は `_scn_div(a, b)`（0の向きへ切り捨てる） |
| `-> シーン`・`@呼出`・`@戻る` | `jump`・`call`・`return`。存在しないシーン（E501）は、行き止まりと同じく知らせてタイトルへ戻る |
| `@エンディング` | コメントとプロファイルの `ending` |
| `@raw renpy` | 中の行をそのまま。ほかのエンジンの `@raw` は読み飛ばして知らせる |
| 知らないディレクティブ（W401） | コメントにして知らせる |
| 変数 | `default`（宣言の初期値。宣言の無い変数は `0`） |
| 素材 | カタログのファイルを写した画像。ファイルの無い画像は、名前入りの色の矩形（仮素材） |

- 実行時の誤り（0での割り算、型の合わない演算、宣言の無い変数に宣言と違う型の値を入れる）は、Ren'Py の例外の画面になる（プレビューは、条件を偽にし、`@設定` を書かずに続ける。仕様書14節）。型の誤りは、書き出す前に `scn check`（E603・E604）で分かる。
