# アプリの使い方

scn-studio のデスクトップアプリの使い方をまとめる。`.scn` の書き方は [`docs/spec/scn-format-v0.md`](../spec/scn-format-v0.md)、作品フォルダの規約は [`docs/spec/project-files.md`](../spec/project-files.md)、コマンド `scn` は [`scn.md`](scn.md) にある。

キーは macOS の書き方（⌘・⌥・⇧）で書く。Windows では ⌘ を Ctrl、⌥ を Alt に読み替える。

## はじめに

- アプリは [Releases](https://github.com/zredjet/scn-studio/releases) の ZIP を展開して使う（インストーラと署名は無い。初めて開くときの OS の警告の越え方は、リリースの説明と README の「ダウンロード」にある）。ソースから作ることもできる（README の「ソースから動かす」）。
- 起動すると「作品フォルダを開く」の画面になる。「作品フォルダを開く」（⌘O）で `project.toml` のあるフォルダを選ぶか、「新しく作る」（⌘N）で空のフォルダにひな形を作る（`scn new` と同じ中身）。前に開いた作品は「最近開いたもの」から開ける。
- 作品フォルダはテキストファイルの集まりで、アプリはそれを読んで画面を作る。アプリだけが持つデータは無いので、Git で管理し、外部のエディタや AI エージェントで直してもよい（[外部のエディタや AI と一緒に使う](#外部のエディタや-ai-と一緒に使う)）。
- 試すときは、リポジトリのサンプル作品 `samples/houkago`（放課後の灯）を開くとよい。

## 画面の構成

| 部位 | 内容 |
| --- | --- |
| タイトルバー | 左：作品のメニュー（最近開いた作品・開く・新しく作る・フォルダを表示・この作品の設定）と Git のブランチ。中央：検索とコマンド（⌘K）。右：AI の様子（local・cloud）、再生、右の欄の開け閉め（⌥⌘B） |
| 左端のバー | 企画・本文・フロー・設定・素材・変数・検証・AI・出力（⌘1〜⌘9）、下に離して環境設定（⌘,） |
| 一覧 | 画面ごとの一覧（シーン、型とエントリ、タスクなど） |
| 作業領域 | 画面の主役。上に見出しの帯 |
| 右の欄 | 選んでいるものの詳細（本文ではカーソルのあるシーンの情報） |
| ステータスバー | 左：画面ごとの情報（文字数、位置など）。右：保存の様子・問題の数・形式の版 |

- **検索とコマンド**（⌘K）：シーン・設定DBのエントリ・素材・コマンドをまとめて探す。`>` で始めるとコマンドだけを探す。何も打たなければ、今の画面で使うコマンドが先に並ぶ。
- **再生**：押すと、本文ではカーソルの位置から、フローでは選んだシーンから、ほかの画面では最初からプレビューを始める。横の ▼ で始め方（最初から、選んだシーンの頭から）を選べる。
- 一度開いた画面は、ほかの画面へ移っても状態（選択、絞り込み、スクロール）が残る。

## 保存のしかた

- **本文**：⌘S で保存する（自動では保存しない）。保存すると、行IDの無い行に行IDが付く。保存していない章は一覧とステータスバーで分かる。
- **フォーム**（設定DB・変数・企画書・環境設定の欄）：欄を離れたとき（変換中でない Enter、選んだとき）にファイルへ書く。保存のボタンは無い。日本語の変換中は書かない。
- **ソース表示**（設定DB・変数・企画のファイルをそのまま直す）：「保存」のボタンか ⌘S。
- 保存していない変更があるまま、作品を閉じる・切り替える・アプリを終えるときは、保存するかを聞く。

## 本文

左の一覧に章とシーンが並ぶ。印はシーンの状態（執筆中・下書き・完成・AI下書き・スタブ）。シーンを選ぶと、その中身（演出、選択、分岐、出口）が一覧の下に開く。

- **執筆表示とソース表示**（⌘/）：執筆表示は、見出し・メタ情報・命令を札にし、行IDを隠して、読みやすくする（本文の文字は変えない）。ソース表示はテキストそのまま（行番号と行IDも見える）。
- **書くときの補助**：補完（話者、シーンID、命令、意味名など）、括弧の補い、三点リーダとダッシュの正規化、段落頭の字下げ。どれも日本語の変換を確定した後に動き、変換中は邪魔をしない。
- **行ID**：保存のときに付く `^k3f9` のような印。執筆表示では隠し、カーソルが入らないように守る。行を分けたり結合したりしても、行IDは仕様どおりに置き直される。
- **検索と置換**（⌘F）：このファイル・すべての章・このシーンから選べる。「本文だけ」で台詞と地の文だけを探せる。すべての章の結果は右の欄に並ぶ。
- **名前の変更**（F2）：カーソルのところのシーンID・キャラクター・変数・設定DBのエントリIDを、作品全体で変える（変わる場所を見せてから）。台詞の本文と行IDは変えない。**定義へ移る**は F12。
- **シーンを開く**（⌘P）：シーンの名前やIDで探して移る。
- **右の欄（このシーン）**：登場キャラ（一人称・口調）、変数の読み書き、素材、このシーンの問題。
- **集中モード**（⌘⇧F）：左端のバーと横の欄を隠す。**タイプライタースクロール**（環境設定）：書いている行をいつも同じ高さに置く。
- **AI が書いた行**は、行の横の線で分かる（実線は AI が書いたまま、点線は人が直したもの）。

## 企画

- **アイデアメモ**：思いついたことを書いて Enter で足す（未整理に入る）。状態（未整理・採用・保留・没）とタグで分け、絞り込める。メモは「昇格」で、設定DBのエントリや、章の末尾のスタブのシーンにできる。
- **企画書**：ログライン、テーマ、トーン、ルート数、想定文字数などのフォームと、主要キャラ（設定DBのキャラクターの欲求と葛藤）。エンディング（到達イメージ）は、本文の `@エンディング` との対応を表で見せる（エンディングを直すのはソース表示で）。対応の無いエンディングは検証でも知らせる。
- **AI**（右の欄）：企画書とメモへの問い返し、メモの分類案、アイデアのネタ出し（方向性と数を伝えて候補を出してもらい、選んだものだけをメモにする）、企画書の下書き。

## フロー

- 粒度（ルート・章・シーン）を切り替え、ルートで絞り込める。「条件を表示」で辺に条件と選択肢の文を出す。
- スタブ（本文の無いシーン）は点線、AI下書きは色付きの枠で見分ける。ノードをダブルクリックすると、そのシーンを本文で開く。
- **図から足す**：「＋ スタブを足す」でスタブのシーンを足し、ノードの端から辺を引くと、ジャンプか選択肢として本文に書き足す（書き込む行を見せてから）。図から消す操作は無い（本文を直す）。
- 動かした位置は作品フォルダの `layout.json` に覚える。「自動整列」で並べ直す（動かした位置があれば、捨ててよいかを聞く）。
- AI：分岐案を出してもらい、提案ノードとして図に重ねて、採用したものだけを本文に書き足す。ルートの骨格を作ることもできる。

## 設定

設定DB（`bible/`）。左に型（キャラクター・場所・組織・伏線など）とエントリ、中央にフォーム、右に逆引き。

- **フォーム**：型の定義に沿った欄（文字、長い文、数、選択肢、ほかのエントリへの参照など）。値が型に合わなければ知らせる。「ソース」でファイルをそのまま直せる。
- **逆引き**：登場シーン、台詞の行数、初出、参照しているもの・されているもの。
- **キャラクター**：呼び名（台詞の話者の判定に使う）、口調、立ち絵の差分（素材カタログと共通）、紐づく変数。
- **型を作る**（＋ 型）：空の型、型のテンプレート、今ある型の複製から作る。型の項目はフォームで直せる。
- **AIに渡す内容**：AI のタスクにこのエントリのどの項目が渡るかを見せる。足りない設定や空欄を AI で下書きすることもできる（値のある項目は書き換えず、案として出す）。

## 素材

素材カタログ（`assets/catalog.yaml`）。本文の意味名（`@背景 屋上/夕方` の「屋上/夕方」）を、ファイルに結びつける。

- 種類（背景・立ち絵・BGM・SE）で分け、「仮素材と未登録だけ」と意味名で絞る。状態は「あり」（ファイルがある）・「仮素材」（カタログにあるがファイルが無い）・「未登録」（本文で使っているがカタログに無い）。ファイルの無い素材は、プレビューでは名前入りの色の矩形（音は無音）になる。
- カタログに無い意味名をカタログに足したり、ファイルを割り当てたりできる。ファイルの場所を Finder（Windows はエクスプローラー）で開ける。
- 立ち絵はキャラクター×差分の表で見る。まだファイルの無い素材は、発注リストとして書き出せる（出力）。

## 変数

`variables.yaml` の変数を、名前空間と問題で絞って並べる。書き・読みの数、宣言（型・初期値・範囲・スコープ）、本文で使っている場所。宣言はフォームで直せる。「取りうる値」は、検証の段階2で調べた道で出た値を見せる。

## 検証

- **段階1**（保存のたびに）：構文、参照（話者・シーン・変数・素材）、構造（行き止まり、到達できないシーン）、メッセージウィンドウのはみ出し、変数の読み書き、企画書のエンディング、伏線。
- **段階2**（「段階2を調べる」で）：開始シーンから選択肢の組み合わせを自動で巡回し、選べない選択肢、真にならない条件、着かないシーン、仕込みを通らない伏線を探す。カバレッジとエンディングごとの到達条件も出る。あわせて、一人称と用語の表記ゆれを調べる。
- 重さ（エラー・警告・情報）で絞り、種類・ファイル・シーンごとにまとめる。行を選ぶと説明と直し方が右に出て、ボタンで本文などの該当の場所へ移る。

## プレビュー

タイトルバーの「再生」か F5（ここから再生）で開く。

- **ADV**：メッセージウィンドウと舞台（背景・立ち絵・BGM）を簡易に表示する。次へ・戻る・オート・スキップ・ログ。右の欄で、今の位置、変数（直せる）、ジャンプ（この状態で開始、最短経路で開始）、選択肢の選び方（毎回止まる、常に1番目、ランダム）、ログを見る。「エディタと同期」で、本文のカーソルが表示中の行へ付いてくる。「別ウィンドウで開く」で別の窓に出せる。
- **縦書き**：道（共通・ルート・エンディング）を選んで通して読む。選んだ選択肢を注記し、字数×行数と原稿用紙換算を出す。
- 「AI下書きを含める」を外すと、AI下書きのシーンを除いて見られる。
- F5 で、カーソルの行から再生する（開始シーンからの最短経路で、変数と舞台をそろえてから）。

## 出力

書き出すものをカードで選び、右の欄で設定して「書き出す」。書き出し先は作品フォルダの `export/` の下（既定）。

| カード | 書き出すもの |
| --- | --- |
| 収録の台本 | 台詞とボイスのファイル名の表（CSV か Excel 形式）。収録の基準を記録すると、変わった台詞に「再収録候補」と書く |
| 発注リスト | まだファイルの無い素材の一覧（CSV） |
| 通読用テキスト | ルートごとに通して読むテキスト（ルビはなろう・カクヨムの記法） |
| Ren'Py・ティラノスクリプト・宴 | そのまま動かせるシナリオ。意味名からファイルへの対応は出力プロファイル（`export/*.yaml`）で決める |
| EPUB・縦書きPDF | 小説として配る形。PDF は印刷用の HTML を書き、Vivliostyle などで組む |
| 書き出しのプラグイン | `export/<名前>.yaml` のテンプレートか外部コマンドで、自分の形式に書き出す。外部コマンドは、この端末で初めて動かす前に確かめる |
| AIの出自 | AI が書いた行と項目の一覧（CSV） |

## AI

AI は使わなくてもよい。使うときは、AI を共作者として扱う：空いているところ（スタブ、空欄）には書き込むが、人が書いた行は直接書き換えず、差分の提案として出す。

### 接続先を用意する

1. 作品フォルダの `project.toml` に接続先を書く（例は README の「AI を使う」と、[`project-files.md`](../spec/project-files.md) の2節）。ローカルの LLM は OpenAI 互換（LM Studio・Ollama・llama.cpp のサーバーなど）、Claude は `provider = "anthropic"`。
2. 「環境設定 → AIの接続」で、接続先ごとに次を決める。
   - キー：OS のキーチェーンに置き、作品フォルダには書かない。
   - Claude の呼び方：API キーか、ログイン済みの Claude Code（CLI）。Claude Code なら CLI の場所を確かめる。
   - クラウドへ送ることの許可：端末ごとに許可するまで、クラウドへは送らない。
   - この端末での上書き：URL、モデル、文脈の長さ、返す分の上限、構造化出力、考える量。ローカルの接続先は、入っているモデルの一覧から選べる。
3. 「接続を試す」でつながるかを確かめる（クラウドは送る中身を見せてから）。

タイトルバーの AI の様子に、local と cloud の接続の状態が出る。

### タスクを実行する

「AI」の画面でタスクを選び、対象（シーン、ルート、章）を決めて実行する。クラウドの接続先では、送る中身（指示と依頼）を見せてから送る。タスクは作品フォルダの `ai/*.yaml` にあり、文面や渡す文脈を直したり、自分のタスクを足したりできる。

| 結果の形 | 例 | 扱い |
| --- | --- | --- |
| 指摘 | 口調チェック、設定矛盾チェック、表記ゆれと誤字、分岐の薄さ | 一覧に並び、エディタの行に印が付く（本文は変えない） |
| 提案 | 言い換え候補 | 今の本文と照らして、行ごとに採用・却下する |
| 下書き | スタブの本文を下書き、章を下書きまで仕上げる | スタブに書き込み、シーンを「AI下書き」にする |
| 要約 | シーン要約 | 要約のキャッシュに入れ、ほかのタスクの文脈に使う |

- **自律**：章のスタブを、展開メモ → 本文 → 点検 → 直す、の順に、反復とトークン数の上限まで進める。Git のブランチを作って書くこともでき、終わったら差分を見て取り込むか捨てる。企画書と設定から始める段も選べる。
- ほかの画面からも頼める：フロー（分岐案、ルートの骨格）、企画（問い返し、分類案、ネタ出し、企画書の下書き）、設定（設定の下書き）。
- **出自**：AI が書いた行と項目は `ai/provenance.jsonl` に記録し、本文とフォームに印を付ける。人が直すと「AI が書いて人が直した」に変わる。一覧は出力の「AIの出自」で書き出せ、書き出しでは「AI下書きを含めない」も選べる。

## 外部のエディタや AI と一緒に使う

- 作品フォルダのテキストが正なので、VS Code（[拡張](../../packages/vscode-scn/README.md)）、ほかのエディタ、Claude Code などの AI エージェントで直してよい。`scn new` が作る `CLAUDE.md`・`FORMAT.md`・`SCN.md` は、AI エージェントが作品フォルダのきまりを読むためのもの。
- アプリは外の変更に気づいて読み直す。保存していない変更とぶつかったときは知らせの帯が出て、外の内容で読み直すか、マージ（ぶつかった行ごとに選ぶ）できる。
- 行IDの無い行は、アプリで保存するか `scn fmt` で付く。外で書いたら、`scn check` で検証できる。

## 困ったとき

- **作品フォルダを開けない**：`project.toml` があるフォルダを選ぶ。`project.toml` の書き方の誤りは、検証の画面に診断として出る。
- **文字が小さい・大きい**：「環境設定 → 文字と表示」の画面の倍率で変える。
- **補完が出ない**：日本語の変換中は出さない（変換を確定してから出る）。
- **AI がつながらない**：「接続を試す」の知らせを読む。OpenAI 互換の URL は `/v1` まで書く。クラウドは、キーと送ることの許可が要る。考えるモデルで答えが空なら、返す分の上限（`output_tokens`）を増やす。
- **書き出したゲームで素材が出ない**：素材カタログでファイルを割り当てる。無い素材は仮素材（名前入りの色の画像）として書き出される。
