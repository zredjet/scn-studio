# Claude Design への頼み（T4-15、2026-10-09）

画面の点検（`audit.md`。T4-11）のうち、見た目の方向を決めるもの（Z5 の③）を、モックの元のデザインキャンバス「ADV執筆ツール 画面UI」で作ってもらうための頼み。Claude Code で直せるもの（T4-12〜T4-14）は直した後の画面を渡す。書き出したモックが届いたら、Claude Code が `docs/ui/mockups/` に置き、反映のタスクを立てる。

## 頼みたいこと

### 2. 部品の組

今は画面ごとに別々に作ってあり、ボタンが9種、札が7種、カードが7種ある。種類を減らした組と、その段階を決めてほしい。

- 見出しの段階（画面、パネル、カード）。今は明朝の24px、ゴシックの20px、18px が混ざる（V5）
- ボタン：主、副、小、危険、リンク風。高さと形（V6）
- 札：ID、状態、件数、AI、仮素材、未登録、警告のコード（V6）
- カード、注意の帯（警告・誤り・情報）、空の状態の文
- 保存の様子：保存中・保存済み・保存していない・誤り。保存のしかたは Z1 のとおり（本文とソースは ⌘S、フォームと環境設定は欄を離れたとき）。言葉と出す場所を全画面でそろえたい（U14）
- 文字の大きさの段階（最小11px、本文17px）。今は15種類が直書き（V7）

### 3. モックの無い画面

- 変数、検証、出力、環境設定
- 重ね表示：コマンドパレット、シーンを開く、名前の変更、スタブのシーンを足す、辺を足す、マージ、保存していない変更の確認
- 本文の検索と置換の欄（T4-14 で足した。今は CodeMirror の欄の並びに色だけ合わせている）

### 4. 画面ごとの直し

- 設定DBのフォーム（V9）：モックは欄を2列に並べ、立ち絵差分の絵と紐づく変数の表をエントリの中に置く。今は1列で長く、上に「空欄をAIで下書き」と注意が来る
- シーン一覧（V4）：モックの章の折りたたみ、状態の点、ルート名、アウトライン。今のシーンの印は T4-13 で入れた
- フローの右の欄（U7）：シーンを選ぶ前に出すもの
- 出力（U18）：カードの並び（収録の台本がいちばん下）と、説明の文の量

## 守る条件

- 色の意味：藍（選択、主な操作、話者、人の書いた構造）、緑青（AI）、琥珀（警告と仮素材）、灰色の点線（スタブ）。色だけで区別せず、線の種類も変える
- 書体は OS のもの（D046）：UI はヒラギノ角ゴシック・游ゴシック、本文は ヒラギノ明朝・游明朝、ID と式は Menlo・Consolas。Zen Kaku Gothic New と Shippori Mincho は使わない前提で、字幅と字面を見る
- UI の部品集は使わない（D003）。値は CSS の変数（`docs/ui/README.md` のトークンの表、`app/src/styles/tokens.css`）にする
- 影とグラデーションは使わず、面の色と線で区切る。押せる部品の高さは28〜36px、文字は最小11px
- 窓の基準は 1440×900、最小は 1024×700。Windows と macOS のデスクトップアプリ
- 明るい外観だけ（Z3）
- 本文の執筆表示は、ソースの1行を1行に飾る形のまま（D046）
- 文言は今の書き方に合わせる（短い平叙文。「〜します」「書き出す」「閉じる」など）
