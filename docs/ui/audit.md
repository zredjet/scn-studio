## 総評

- 色の意味（藍は選択と人の書いた構造、緑青は AI、琥珀は警告と仮素材、点線はスタブ）は全画面で守られている。プレビュー、素材カタログ、変数の表、フローの節の見た目はモックに近い
- 操作感で困るのは3つ。下書きが黙って消えること（U1〜U4）、画面を移るたびに状態が消えること（U5）、キーボードと Esc の扱いがそろっていないこと（U9〜U12）
- 見た目で困るのは3つ。狭い窓で崩れること（V1）、骨格（タイトルバー、左端のバー、シーン一覧）がモックより情報が少ないこと（V2〜V4）、部品と文字の大きさに決まりが無く画面ごとに違うこと（V5〜V7）

## Claude Design に渡すもの

モックの元のキャンバス（「ADV執筆ツール 画面UI」）で、次の案を作ってもらう。書き出したモックは `docs/ui/mockups/` に戻し、Claude Code が実装に反映する。

**案が要るもの**

1. 骨格：タイトルバー（V2）、アイコン付きの左端のバー（V3）、画面ごとのステータスバーの中身（U15）、AI の接続の様子を一度だけ示す場所（U19）
2. 狭い窓（1024〜1280）での骨格と、各画面の回り込み（V1。Z2 の決定に沿う）
3. 部品の組：見出しの段階、ボタン（主・副・小・危険）、札、カード、注意の帯、保存の様子の出し方（V5〜V7、U14）
4. モックの無い画面：変数、検証、出力、環境設定、重ね表示（スタブを足す、辺、名前の変更、マージ、パレット）
5. 設定DBのフォームの組み方（V9）、シーン一覧で足すもの（V4）、フローの右のパネルの選ぶ前の中身（U7）、出力の並び（U18）

**守る条件**

- 色の意味：藍（選択、主な操作、話者、人の書いた構造）、緑青（AI）、琥珀（警告と仮素材）、灰色の点線（スタブ）。色だけで区別せず、線の種類も変える（`docs/ui/README.md` の「色の意味」）
- 書体は OS のもの（ヒラギノ・游。D046）で見た目を決める
- UI の部品集は使わない（D003）。トークンは CSS の変数にする
- 影とグラデーションは使わず、面の色と線で区切る。押せる部品の高さは28〜36px、文字は最小11px
- 窓の基準は 1440×900。デスクトップアプリ（Windows と macOS）
- 本文の執筆表示は、ソースの1行を1行に飾る形のまま（D046）

**添える画像**（`target/ui-audit/screens/`）

`01-ideas`、`02-editor-writing`、`02b-editor-source`、`02c-editor-context`、`03-flow-scene`、`03-flow-route`、`04-bible`、`05-assets`、`06-preview`、`06b-preview-vertical`、`07-ai`、`08-variables`、`09-check`、`10-export`、`10b-export-bottom`、`11-preferences`、`12-palette`、`12b-quick-open`、`13-narrow-flow`、`13-narrow-editor`、`13-narrow-bible`、`17-flow-stub-dialog-escape`

タイトルバーには、この端末のローカルのモデル名と作業用の写しのパス（素材の画面）が写っている。外へ渡すときは気をつける。
