# 設計検討書との突き合わせ（T3-17）

フェーズ3の締めくくり（`docs/plan/phase3.md` の T3-17 の手順2）。設計検討書（`docs/design.md`）の節ごとに、作ったもの・一部だけ作ったもの・作っていないもの・違えたものを並べる。2026-10-09 の作業ツリー（T3-16 まで）で、設計検討書の文ごとに、コード（`crates/`・`app/`・`packages/`）、仕様書（`docs/spec/*.md`）、決定（D001〜D077）、計画、進捗を照らした。「作った」は自動で確かめられる範囲のことで、人の確認（`docs/review-for-human.md` の2節、H1〜H30）はすべて未。

作っていないもの・一部だけ作ったものの残り・決めずに残したものは、人が決められるように `docs/review-for-human.md` の3節（X1〜X16）にまとめた。

## 要約

- ロードマップのフェーズ0〜3の中身は、自動で確かめられる範囲ではすべて作った。各フェーズのゲートと、フェーズ3を閉じる条件の人の確認（H1〜H30）は、すべて未。
- 作っていないもの：7件（形式の移行、命令の日英名をそろえる整形、マクロ、行IDで引く翻訳・コメント・既読、索引の保存とサムネイル、MCP サーバー、配布）。
- 違えたもの：18件。どれも理由の決定がある（下の表）。
- 一部だけ作ったもの：Windows での確認がすべて未。補完と定義へ移動の決まりがアプリ（TS）とコア（Rust）に2つあり、アプリのエディタには参照検索とホバーが無い（X11）。ほかに細かいもの（下の表。残りは X16）。
