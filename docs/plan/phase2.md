# フェーズ2 作業手順：制作に使える

フェーズ2では、書いた作品を実際のゲームの制作に渡せるようにする。Ren'Pyへの書き出し、素材カタログと発注リスト、カーソル位置からの再生と別ウィンドウのプレビュー、縦書きでの通読、企画とアイデアメモの画面、外部エディタとの同時編集のマージを作る。フェーズ1で「フェーズ2で作る」とした細部（F2のリネーム、フロー図からの編集、設定DBの型定義の編集など）もここで片づける。

状態：草案（2026-10-08、T1-13で作った）。人の指示（「設計検討書の範囲を全て遂行する。確認したいことは推奨で進め、まとめておく」）により、人の確認を待たずにこの草案で進める。違う線引きにしたいものがあれば、`docs/review-for-human.md` に書いた判断と同じく、番号を添えて伝えてほしい。`docs/design.md` のロードマップ、フェーズ1の記録（`docs/progress.md`）、`docs/decisions.md` の D040 から作った。

## ゲート（フェーズ3へ進む条件）

1. 書き出したRen'Pyのプロジェクトが起動し、最後まで遊べる（`docs/design.md` のロードマップ）。
   - `samples/amayadori` を書き出し、Ren'Pyの SDK で起動して、3つのエンディングすべてまで遊べる。`samples/houkago` は akari_end と tsumugi_end まで遊べる（bad_end は選択肢だけでは着けない（D050）ので、Ren'Py のコンソールで `jump s030` を使う。true_end は本文に無い）。人がRen'Pyを入れた環境で確かめる
   - 書き出しのスナップショットのテストがあり、Ren'Pyの `lint` を通る（SDK のある環境で）
2. フェーズ1から持ち越した人の確認（`docs/review-for-human.md` の2節の H1〜H8）が済んでいる。WindowsとmacOSで、`docs/plan/ime-test.md` の必須項目（フェーズ2で足す項目を含む）がすべて合格する。

## Claude Code（Opus 5.5）での進め方

フェーズ1と同じく、1タスクを1セッションで扱い、`/phase-task T2-2` のように依頼する。人に確認する判断は、人の指示で推奨案で決めて `docs/review-for-human.md` の1節に、人の環境でしか確かめられないことは2節に書く。

- 画面を作るタスクは、確認用のページ（Vite で画面だけを描く）を内蔵ブラウザで開いて、見た目を自分で確かめてから、人の確認を2節に書く。確認用のページはコミットしない。
- 書き出しのタスク（T2-2、T2-3、T2-5、T2-10）は、サンプルの書き出しのスナップショットを置く。
- 新しい診断コードを足すときは、仕様書の診断表と fixture を先に足してから実装する（`.claude/rules/rust.md`）。

## T2-2 Ren'Pyへの書き出し

**目的**：IRを、出力プロファイル（`export/renpy.yaml`）に従ってRen'Pyのスクリプトに書き出す（`docs/design.md` の「エクスポート」と「プロファイルと変換例（Ren'Py）」）。

**手順**

1. 出力プロファイルの形を決め、`docs/spec/project-files.md` に書く：対象（`target: renpy`）、画像の名前の付け方（背景・立ち絵）、位置とトランジションと `@効果` の対応、ボイスのファイル名、キャラIDと変数名をRen'Pyで安全な名前にする対応表、書き出し先。サンプルの `export/renpy.yaml` を出発点にする。
2. コアに書き出しを作る（`export` モジュール）：シーンはラベル、`@背景`・`@立ち絵`・`@退場`・`@BGM`・`@SE` は `scene`・`show`・`hide`・`play`、選択肢は `menu`（条件つき）、`@if` は `if`、`@設定` は `$`、ジャンプと呼び出しは `jump`・`call`・`return`、エンディングは `return`（またはプロファイルで決める）、キャラクターは `Character` の定義、変数は `default`、ルビ・傍点・`{w}`・`{p}`・`{speed}` はRen'Pyのテキストタグ、`@raw renpy` はそのまま、ほかのエンジンの `@raw` は警告つきで読み飛ばす。素材は、カタログのファイルを書き出し先に写すか参照する（推奨案で決める）。
3. CLI（`scn export renpy`）とアプリの「出力」の画面の両方から出す。書き出しは一方向（生成物を手で直さない）。
4. サンプルの書き出しのスナップショットを置く。Ren'Pyの SDK があれば `lint` を通す（無ければ人の確認に回す）。
5. マクロ（`docs/design.md` の「エンジン側で必要な調整は `@raw` とマクロで本文側に吸収する」、仕様書10節の W401）の扱いを決める（推奨案で決める。作るならフェーズ2の範囲で最小に）。

**完了条件**

- [x] 出力プロファイルの形が `docs/spec/project-files.md` にあり、プロファイルの誤りの診断（足すなら仕様書の診断表と fixture）がある（11節。誤りは診断コードを足さず、書き出しのときに知らせる。R41）
- [x] `samples/houkago` と `samples/amayadori` の書き出しのスナップショットがある
- [ ] 人がRen'Pyで起動し、エンディングまで遊べることを確かめた（H9。自動では `scripts/renpy-check` で、SDK の lint と全エンディングまでの自動プレイが通っている）
- [x] `scripts/check-all` が成功する

**やらないこと**：ティラノスクリプト、宴、EPUB・縦書きPDF、外部コマンド型のプラグイン（フェーズ3）。
