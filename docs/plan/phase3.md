## Claude Code（Opus 5.5）での進め方

フェーズ2と同じく、1タスクを1セッションで扱い、`/phase-task T3-2` のように依頼する。人に確認する判断は、人の指示で推奨案で決めて `docs/review-for-human.md` の1節に、人の環境でしか確かめられないことは2節に書く。

- 画面を作るタスクは、確認用のページ（Vite で画面だけを描く。コアの呼び出しは模擬）を内蔵ブラウザで開いて、見た目を自分で確かめてから、人の確認を2節に書く。確認用のページはコミットしない。
- AIのタスクは、自動のテストで実際のLLMを呼ばない。コアのテストは、テストの中で立てる模擬のサーバー（OpenAI 互換と、ネイティブの接続（Anthropic の Messages API）。標準ライブラリの `TcpListener` で、決めた応答を返す）で確かめる。クラウドへの送信は、人が接続先ごとに有効にしたときだけ行う（設計検討書「接続」）。
- 書き出しのタスク（T3-11〜T3-14）は、サンプルの書き出しのスナップショットを置く。
- 新しい診断コードを足すときは、仕様書の診断表と fixture を先に足してから実装する（`.claude/rules/rust.md`）。
- 新しい依存は、設計検討書の「アーキテクチャ」に名前のあるもの（`reqwest`、`keyring`、`minijinja`、`tower-lsp`。`tower-lsp` は保守の状況を確かめ、フォークを使うかを T3-15 で決める）を使う。Git の操作は `git` コマンドを呼ぶ（依存を足さない。T3-9）。VS Code拡張は `packages/vscode-scn` の中だけで、拡張に要る定番のパッケージ（言語クライアント、テストとパッケージの道具）を使う（T3-16）。それ以外の大きな依存は推奨案で決めて、`docs/review-for-human.md` に書く。
- 設計検討書に無い、確かめるための小さな道具（`scn ai context`、`scn provenance` など）は足してよい。

## T3-5 AIの接続とキーの保管

**目的**：コアから LLM を呼べるようにする（`docs/design.md` の「接続」）。

**手順**

1. コアに共通の呼び出し口を作る（`ai` モジュール）：OpenAI互換の API（チャットの補完。ストリーミングの扱いを決める）を基本のアダプタにし、Ollama・LM Studio・llama.cpp のサーバー・互換のクラウドをまとめて扱う。タイムアウト、取り消し、トークン数の数え方（応答の `usage`）を決める。
2. 接続先の設定をどこに置くかを決める（推奨案で決める）。作品フォルダの `project.toml` には `[ai.local]`・`[ai.cloud]` の枠が予約してあり（`docs/spec/project-files.md` の2節。サンプルに `provider`・`base_url`・`model` がある）、AIタスクの定義の `model: local` / `model: cloud` はこれを指す。チームで共有してよいもの（種類、モデル）は作品フォルダに、端末ごとのもの（URL の上書き、クラウドへの送信を有効にしたか）とキーは端末側に置く、のように分ける案が候補。規約の2節を更新する。
3. ネイティブのアダプタを作る：OpenAI互換でないサービスのうち、少なくともサンプルの `[ai.cloud]` の `provider = "anthropic"`（Messages API）を作る（`docs/design.md` の「接続」：互換でないサービスはネイティブのアダプタで足す）。知らない `provider` は、使うときに知らせる。
4. APIキーは OS のキーチェーンに保存し（`keyring`）、フロントには渡さない。クラウドへの送信は接続先ごとに有効にしたときだけ行い、送る中身を前もって見せる。既定はローカル。
5. アプリの環境設定（左端のバーの「環境設定」）に接続先の画面を作る。タイトルバーに今の接続先を出す（`docs/ui/README.md`）。
